# AGENTS.md — logger

`@neutronai/logger` is the repo's ONE leveled key=value logger (refactor O1). `createLogger(subsystem)` emits `[subsystem] event=<event> k=v` lines (the `LOG_TAG event=… k=v` convention from chat-bridge/reminder-outbound), gated by `NEUTRON_LOG_LEVEL` (`error|warn|info|debug`, default `info`, re-read on every emit). Values with whitespace/quotes/`=`/backslashes/control chars are logfmt-quoted with backslash escapes so lines stay single-line and whitespace-splittable. Suppression helpers generalize three existing hand-rolled patterns with matching semantics: `once(key)` (the GBrain `latchIfUnavailable` process latch — exactly one line per key), `clearOnce(key)` (the rate-limit-banner edge-triggered latch's falling edge — rising edge fires `once`, falling edge re-arms), and `rateLimited(key, ms)` (the wedge-alert `alertDedupeMs` cooldown — suppressed while `0 <= now - last < ms`, stamped only on an attempt that clears BOTH the level gate and the window gate, so suppressed or level-gated attempts never extend the window). `rateLimited` deviates from the wedge-alert original in two deliberate ways that change observable suppression, and they break different halves of "one line per window" (a third difference is in the clock reads: the gate and the stamp call `clock()` separately — the gate's read is skipped on a key's first emit — where the original captures a single `now` and reuses it, so the anchor written here is a later reading than the one eligibility was decided on and the next boundary moves out by the gap between the two reads; negligible on a real clock, whatever the test makes it with a counter-style injected clock). Treat that as the set of differences looked for, not a proof no fourth exists: an earlier revision claimed "ONE deliberate exception" and documented a second one in the same paragraph. **(1) The stamp lands immediately *before* the sink call**, so it records an attempted delivery, not a confirmed one — a `sink` that THROWS consumes the window and the throw propagates. That is the safe side on purpose (stamping afterwards would let a persistently-throwing sink re-attempt on every call, the flood these windows exist to prevent), but it means the bound is on ATTEMPTS, not delivered lines, and it is a real deviation: the original stamps AFTER its delivery call returns (`supervision.ts` — `postAlert?.()` then `wedgeAlertState.set(...)`), so a throwing alert leaves the original's window open and does not leave ours open. This is **not** limited to injected sinks — the default sink dispatches to `console.*`, which throws on `EPIPE` when the pipe's read end is gone (a merely full pipe blocks or gives `EAGAIN` instead) and under a throwing test mock; executed with no sink injected, one throwing attempt consumed a 600 s window and a recovered `console.log` was still suppressed. **(2) A BACKWARD clock step (negative elapsed) EMITS**, because `Date.now()` is not monotonic and a plain `now - last < ms` would suppress the key for step + `ms` — an hour-long NTP correction would silence a 10-minute heartbeat for 70 minutes, reading as the "it died" alarm the heartbeat exists to rule out. The emit re-stamps, so the window self-heals. **So: at most one line per window under a forward-only clock (a backward step can give MORE), and no guarantee any window delivers a line at all (a throwing sink gives ZERO)** — reason from `0 <= now - last < ms`, not from `now - last < ms`. Latch state is per-process module state keyed `subsystem × key`, shared across logger instances. Sink and clock are injectable (`LoggerOptions.sink` / `.now`) for tests and DI seams.

This package is a `contracts`-band LEAF: it must import NOTHING from the workspace (dependency-cruiser enforces it). Broad `console.*` call-site adoption is still O2. F3, however, ALREADY imports this package from production host code: `logger/fire-and-forget.ts` exports `fireAndForget` / `neutralizeAbandonedSettle` (fire-and-forget rejection visibility) + `installProcessSafetyNet` (the process-level unhandledRejection/uncaughtException net), and host packages import them (e.g. `gateway/index.ts`, every standalone entrypoint, ~18 workspace packages). Allowed dependency direction: host code MAY import `@neutronai/logger` (a contracts-band leaf); the leaf still imports nothing back. Bundled Cores + the `loop` leaf must NOT import it (see the F3 gate exclusions + the `cores-use-sdk-only` dependency-cruiser rule).
