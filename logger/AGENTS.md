# AGENTS.md — logger

`@neutronai/logger` is the repo's ONE leveled key=value logger (refactor O1). `createLogger(subsystem)` emits `[subsystem] event=<event> k=v` lines (the `LOG_TAG event=… k=v` convention from chat-bridge/reminder-outbound), gated by `NEUTRON_LOG_LEVEL` (`error|warn|info|debug`, default `info`, re-read on every emit). Values with whitespace/quotes/`=`/backslashes/control chars are logfmt-quoted with backslash escapes so lines stay single-line and whitespace-splittable. Suppression helpers generalize three existing hand-rolled patterns: `once(key)` (the GBrain `latchIfUnavailable` process latch — exactly one line per key), `clearOnce(key)` (the rate-limit-banner edge-triggered latch's falling edge — rising edge fires `once`, falling edge re-arms), and `rateLimited(key, ms)` (the wedge-alert `alertDedupeMs` cooldown — a throttle for a line that must keep appearing without flooding; a suppressed or level-gated attempt never extends the window). `rateLimited` is close to the wedge-alert original but deliberately not bit-for-bit. Departures worth knowing about, and not an inventory of every difference: **a BACKWARD clock step emits rather than suppressing** — `Date.now()` is not monotonic, and a throttle that trusts it would silence a key for the step plus the window, which for a heartbeat reads as the "it died" alarm the heartbeat exists to rule out; the emit re-stamps, so the window self-heals. And **the window is consumed just BEFORE the sink runs**, so a throwing sink consumes it anyway and a consumed window is no evidence a line reached anyone — the safe side on purpose, because stamping afterwards would let a persistently-throwing sink re-attempt on every call, the flood the window exists to prevent; reachable with no sink injected, since the default sink calls `console.*`, a mutable global. A caller needing a DELIVERY bound rather than an ATTEMPT bound must make its own sink non-throwing. **`logger/__tests__/logger.test.ts` is the place to learn what it actually does — read the cases, not a prose restatement of them.** Its `rateLimited` cases all use a non-throwing sink, so the throwing-sink behaviour above is a reading of `emit` rather than something the suite pins; rely on the code for it, not on this file. Successive revisions of this file restated the predicate and counted the deviations from the original, and the restatements and the counts are what kept being wrong; the intent survived every round. Latch state is per-process module state keyed `subsystem × key`, shared across logger instances. Sink and clock are injectable (`LoggerOptions.sink` / `.now`) for tests and DI seams.

This package is a `contracts`-band LEAF: it must import NOTHING from the workspace (dependency-cruiser enforces it). Broad `console.*` call-site adoption is still O2. F3, however, ALREADY imports this package from production host code: `logger/fire-and-forget.ts` exports `fireAndForget` / `neutralizeAbandonedSettle` (fire-and-forget rejection visibility) + `installProcessSafetyNet` (the process-level unhandledRejection/uncaughtException net), and host packages import them (e.g. `gateway/index.ts`, every standalone entrypoint, ~18 workspace packages). Allowed dependency direction: host code MAY import `@neutronai/logger` (a contracts-band leaf); the leaf still imports nothing back. Bundled Cores + the `loop` leaf must NOT import it (see the F3 gate exclusions + the `cores-use-sdk-only` dependency-cruiser rule).
