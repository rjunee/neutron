## 2026-09-24 — REPL cleanup tests inspect their own config paths

The owner MCP server tests used a before/after census of every `neutron-repl-*` directory in the shared temporary directory. A parallel suite could create a legitimate REPL during either test and be reported as a leak. The two assertions now take the exact `--mcp-config` path from their own host spawn. The failed-spawn case captures argv before throwing; the concurrent-dispatch case uses its one captured spawn. Both require the config file to exist and its parent to be mode 0700 before cleanup, then require both paths to be absent afterward. The latter also requires exactly one child to have spawned and been killed.
