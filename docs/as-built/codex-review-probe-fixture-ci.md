## 2026-09-23 — Make the Codex review probe fixture reliable in CI

Issue #1225 records a red `shard 4/4` on Trident-owned PR #1213. Its only failure was `runtime/workers/codex-review.test.ts:83`: a recovery that should have returned `unknown` returned `refused` after 5,035 ms. The PR changed only retry visibility documentation and `trident/infra-retry.test.ts`; the failing test and its runtime drivers had identical Git blobs on the PR base and then-current main. On that main, the isolated file passed 42/42 and the affected case took 242 ms. The exact refusal reason was not captured by the assertion, so the five-second CLI probe timeout was a supported timing hypothesis, not a proven runtime defect.

The fixture previously started a Node process for each fake CLI capability probe. The production contract requires those probes, including the `resume` subcommand, the sandbox configuration key, and a final unknown sentinel (`docs/spec-items/codex-work-runs-headless-per-call-on-a-reused-thread.md:453-490`). A small shell shim now answers only those fixture probes. Before writing the expected probe record, it checks the actual argument count and values, including the sandbox setting followed by the sentinel. The existing Node fixture still handles the simulated model turn, including its JSON envelope, usage, interruption and recovery cases. No production file or probe timeout changed.

The baseline test file passed 42/42 in 2.85 s with the shim. Its first recovery case took 77 ms. Both directions of the probe guard were exercised on the changed fixture and restored: a mutant that made the bad sandbox report the sentinel caused `startup bad-sandbox refuses admission without any model turn` to fail because the runner admitted it; a mutant that made the valid sandbox report an invalid key caused `startup validates sandbox before a final sentinel and ignores user config` to fail because the runner refused it. Two production argument mutants were also run against the new fixture: putting the sentinel before the sandbox setting, and removing the sandbox setting. Each made the startup acceptance test red; restoring the production file returned the focused suite to 42/42 green. `git diff --exit-code -- runtime/workers/codex-review.ts` confirmed no production change remained.

The combined Codex review and Open project build consuming suite passed 304/304, zero failures, in 318.54 s with the Unix socket permission those tests require. `tsc -p tsconfig.json --noEmit` and `tsc -p trident/tsconfig.json --noEmit` both exited zero. The as-built is part of this change and the frozen `docs/AS_BUILT.md` was not edited.
