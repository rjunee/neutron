## 2026-10-03 — Await verified Herdr pane closure during project placement

Herdr can answer `pane.close` with typed `terminal_exit_pending` while it finishes child exit and PTY EOF. Project placement previously treated that reply as a failed close. During Chat creation, the failure handler then closed the new Chat pane and left the workspace pending, although the old initial shell could disappear shortly afterward.

The manager now waits a bounded interval for `pane.get` to report typed `pane_not_found` for that exact handle. Before publishing ready placement, it verifies the protocol and the recorded workspace ownership marker through the same RPC client. The wait applies to the initial shell in both Chat-first and worker-first creation and to a verified inert Chat placeholder. Other close errors, failed observations, mismatched ownership, protocol drift, and a still-live pane preserve the pending claim. An uncertain observation after the pending reply also leaves the newly created Chat pane untouched, since the server may have changed. No tab or workspace close was added; foreign split panes survive placeholder retirement.

Verification: the workspace/host suite passed 80 tests, including deferred closure, timeout, transport failure, unrelated typed refusal, changed ownership, protocol drift, changed live pane placement, and foreign split controls. Open composition passed 18 tests. Root and Trident TypeScript checks passed. Focused controls failed when mutated to publish before observing closure; treat every typed refusal as pending; remove protocol, owner-token, or live-pane placement verification; clean up after uncertain ownership; or skip cleanup for ordinary close refusals.
