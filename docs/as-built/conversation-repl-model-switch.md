## 2026-09-19 — Surface native conversation model controls

The locked harness pivot requires the owner to see the current conversation model and switch between planning and cheaper orchestration models in place on phone and web. This change adds a scoped, bearer-protected current/list/switch surface and visible controls in both clients. A switch is conditional on the observed session identity; neither client reports success until the native picker confirms the requested current model. Stale responses, unavailable models, busy turns, wrong scopes, and missing native acknowledgement remain explicit refusals.

The Claude control selects the native picker's session-only choice, never the shared default. An explicit owner selection survives a resume of that same conversation; fresh chats and auxiliary substrates retain the default frontier floor. The Codex control observes its native picker on an already-hosted session. No GET starts a session, and a Codex provider without a composed live chat session reports unsupported rather than fabricating a current model. Legacy sessions without an unambiguous conversation scope marker also refuse model control; this change does not reinterpret an ambiguous General registry row.

Measured locally: the native runtime's focused suite passed 233 tests; the integrated phone, web, HTTP/runtime, and project-build consuming suites passed when run in their own test environments; root, app, web, and Trident TypeScript checks passed. Mutation tests made missing native acknowledgement, General-scope aliasing, over-applied model flooring, and removed default flooring fail. This is not live cutover proof: the deployed phone/web path and context continuity still require a live test, and ordinary Codex owner chat is not yet composed on the hosted project REPL.
