## 2026-09-24 — Scope voice-note retry assertions to the clip request

Refs #1241. The web retry test replaced the process-wide `fetch` and counted every request as a voice-note restore. In a co-resident test process, an unrelated request could therefore produce `expected: 1, received: 2` without a duplicate clip fetch. A controlled probe issued one unrelated `data:` request between mount and the first assertion: the old test failed with exactly that mismatch while the clip had been requested once. This demonstrates the test's false-positive path; the live failed run did not record request URLs, so its second request cannot be attributed retrospectively.

The replacement now refuses and counts only the resolved clip URL, forwarding other requests to the fetch implementation it replaced. The test proves an unrelated request is forwarded without changing the clip count, then still requires exactly one clip attempt before the retry tap and exactly two after it. A second same-clip fetch inserted into the component made the first count fail (`2` versus `1`); removing the retry attempt increment made the second count fail (`1` versus `2`). Both mutations were reverted.

The separate 42-file device-lane failure at the live base and then-current main was also measured: both runs exited nonzero with 399 passes and 10 native voice-note failures because another test installed a process-wide inert `expo-audio` mock. That collision was fixed separately in #1242. With both fixes on the rebased head, the current content-derived device lane passed 410/410 across 43 files (one new harness file joined the lane). The isolated 14-case voice-note test and both root and app TypeScript checks passed. The full-suite CI receipt remains required for G063; a device-lane pass alone does not establish it.
