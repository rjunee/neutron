## 2026-09-24 — Scope voice-note retry assertions to the clip request

Refs #1241. The web retry test replaced the process-wide `fetch` and counted every request as a voice-note restore. In a co-resident test process, an unrelated request could therefore produce `expected: 1, received: 2` without a duplicate clip fetch. A controlled probe issued one unrelated `data:` request between mount and the first assertion: the old test failed with exactly that mismatch while the clip had been requested once. This demonstrates the test's false-positive path; the live failed run did not record request URLs, so its second request cannot be attributed retrospectively.

The replacement now refuses and counts only the resolved clip URL, forwarding other requests to the fetch implementation it replaced. The test puts a sentinel around that downstream implementation: an unrelated `data:` request must reach the sentinel and return its expected HTTP status and body, without changing the clip count. The prior check recorded a claimed forward before the delegate call, so replacing the call with a throw could leave that assertion green; the sentinel and response now make that mutation fail. The test still requires exactly one clip attempt before the retry tap and exactly two after it. A second same-clip fetch inserted into the component made the first count fail (`2` versus `1`); removing the retry attempt increment made the second count fail (`1` versus `2`). Both mutations were reverted.
