## 2026-09-26 — Recover a proven dead Codex owner without replacing its conversation

The durable opener previously adopted only a live authenticated helper or
followed a completed explicit retirement. An ordinary helper crash left the
launch journal in place and refused the next attachment. The opener now records
a distinct crash receipt and reserves the same deterministic successor directory
used by exact-thread resume. It preserves the predecessor attestation, launch
scope and transcript. A crash receipt never claims that retirement completed.

`project-owner-crash-recovery.ts` corroborates the descriptor and pane against
the sealed bootstrap SQLite generation before admitting recovery. It proves
helper, terminal and native process death using boot and birth identity, and
refuses an incomplete process census or a competing credential-home/thread
owner. New bootstrap attestations include both child identities. Legacy
attestations without those identities can recover after a proven machine reboot;
same-boot legacy crashes remain refused. No signal or PID-based termination was
added; the existing death verifier moved unchanged into
`project-owner-generation.ts`.

`CodexOwnerBindings.recoverExisting` returns adoption, resume, skipped or an
explicit refusal with retryability. Missing owners and completed retirements
remain asleep. A temporary Herdr inspection failure can retry before attachment.
An idle disconnected frontend can detach and reopen through independent native
proof; admitted work, review leases and durable unknown-work markers prevent
that cache replacement. Recovery never submits a model prompt or changes
providers. The shared boot scheduler is integrated separately.

Validation used temporary files and SQLite databases, injected process evidence,
and mocked attachment/Herdr boundaries. Twenty focused cases cover both successful
resume/adoption and live, foreign, unknown, changed-generation, changed-credential,
interrupted-retirement and unknown-work refusals. Two selected existing boot
binding cases pass as well. Native process/reboot smoke tests and the full suite
were deliberately not run in this workstream; this is not a live restart receipt.
Root, Open and Trident TypeScript checks pass.
As a must-fail control, omitting the competing-owner census made its refusal
test fail by producing a crash receipt; restoring the census made it pass again.

The remaining interrupted-work boundary is explicit: restoring the native
conversation does not adjudicate an existing `.neutron-owner-work.json` or replay
its request. Such work remains fenced until the workflow's authoritative result
and lease reconciliation completes. This change alone does not establish full
automatic continuation of interrupted workflows.
