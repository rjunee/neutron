## Limits, uncertainties, and continuous enforcement

This is a bounded inventory of the three named loop files and the explicitly followed boundary owners, **not a proof that every transitive dependency is covered**. Compound conditions are grouped by the decision they protect; rows and raw grep hits do not correspond one-to-one. Lexical searches can miss computed dispatch, dynamically constructed commands, a new synonym, an indirect helper, or a condition whose significance is not evident from its name. Test declarations can miss assertions inside generic fixtures or generated cases; this is why NO TEST is an unresolved pin, not an absence theorem. A positive control proves the search works on that spelling, not that the spelling spans every implementation.

The delegated mutation validator (G143) retains ownership of its many argument spellings; this document does not enumerate each runner-option alias. Transitive rebase/arbiter and bound-review checks are not exhaustively expanded here. Host credential resolution, dispatch admission, scheduler concurrency, Workflow runtime token accounting, GitHub branch protection, and CI's own leak scanner are outside the three-file audit boundary. They must not be mistaken for guards implemented by these files. This slice adds no runtime token-budget gate merely because `budget.spent()` appears in logging (`pre-#845 trident/inner-workflow.mjs:7630`).

G139 and G140 are deliberately included even though they do not refuse: preflight and single-family warnings are easy to mistake for hard gates. G132–G134, G136–G138 and G159 include prompt requirements and data boundaries because losing them changes what a review or build can mean. They depend on the agent following its instructions; they are not independent enforcement. G135 is independently enforced only in clones whose versioned hooks are installed; otherwise its wrapper invocation remains prompt-routed (`.githooks/pre-commit:4`, `pre-#845 trident/inner-workflow.mjs:1686`). Cleanup is a deterministic command, but its invocation remains an agent boundary (`pre-#845 trident/inner-workflow.mjs:9291`).

Code-level gates are maintained by the loop's comparisons on every transition. Retry/recovery bounds also rely on persisted counts and atomic claims (G079–G082, G114). The outer watchdog remains a backstop when the inner workflow cannot persist a failure (G123–G124), so that backstop does not require the failed inner agent to cooperate; it still requires the outer ticker and storage to run. Cleanup in finally similarly does not require a valid builder result, but process death can prevent finally from executing (G125). This document introduces no new invariant or enforcement mechanism and makes no broader crash-survival claim.

No code or tests were changed, no new guard was added, and no mutation experiment was performed in this documentation slice. Existing test references are preservation targets for the replacement lane, not permission to weaken tests or a claim that all cited tests were run here.
