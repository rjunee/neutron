# IMPLEMENTATION_PLAN — A gateway restart must not kill an in-flight build: recover from the pushed branch instead of reaping the run

Governing spec: this Plan card (owner instruction 2026-08-14: "Gateway restarts should not kill a build. The build should recover."). Verified against main 2026-08-14:

- The defect is exactly where the card says: `open/wiring/substrates.ts:429-434` (`onChildCrash` → `TridentRunStore.crashRunningByLauncher`) stamps `subagent_status='crashed'`, and `trident/orchestrator.ts` `step()` §1a (~1033-1053) reaps any `crashed` row with no parseable `inner_result` straight to `failed` ("A crashed launcher is a DEAD RUN…"). The durable continuation state (`branch`, `pr`, `inner_checkpoint`, `round`, `ralph_round`) is already on the row and already folded into `launch()` (`resume_checkpoint`, `detectExistingPr`, pr/branch reuse) — the relaunch machinery exists; only the routing is missing.
- LOAD-BEARING TRAP the fix must design around: `saveIfActive` (`trident/store.ts:626-684`) VETOES any non-crashed write onto a row latched `crashed`, and re-latches `crashed` for a 'running' write whose `workflow_run_id` has a tombstone in `trident_launcher_crashes`. So recovery MUST clear the latch out-of-band (atomic store write) before relaunching, and MUST null `workflow_run_id` so `launch()`'s `outcome.launcher_session_key ?? launchRun.workflow_run_id ?? id` fallback can never re-adopt a tombstoned generation.
- The recovery budget must be DURABLE (a new `crash_recoveries` column): the deploy-loop cause (three gateway restarts in 53 min) resets every in-memory counter each boot — an in-memory bound cannot cap it. It must be SEPARATE from `round`/`ralph_round` (acceptance (b): these are not the agent's failures).
- Delivery hazard found in survey: `trident/delivery.ts:204` routes any reason containing "exhausted" to the review-unresolved class ("the reviewer still had blocking findings") — a budget-exhausted crash reason containing that word would misreport, the exact #240 failure shape. The new terminal reason needs its own classifier branch, checked before that line.
- `crash-before-launch-save.test.ts` pins today's REAP as the fix for unbounded refire. Its real invariant is BOUNDEDNESS, not reaping — it must be updated to the budget-bounded contract, never weakened (an always-crashing launcher still terminates, with bounded fires).
