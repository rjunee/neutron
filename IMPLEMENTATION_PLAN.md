- DECIDED — WHEN: the rebase lives in the OUTER publisher, between the local-tip verification and the lease observation/push. Only the outer loop holds a push credential (the Forge sandbox strips `*TOKEN*`), so "rebase + re-push before the readiness probe" can only happen there; and because the publisher fires after EVERY build/fix round and before EVERY review re-fire, every fix round re-enters a branch already based on current main — post-round-1 code IS written against the tree it merges into, the closest to "before build" the credential boundary allows.
- DECIDED — MECHANISM (shallow-safe, governance #574/#571): never `git rebase` in the shared checkout (`.git/shallow` boundary makes merge-base lie). Replay the branch's own diff onto the OBSERVED base tip in a throwaway detached worktree: PR exists → `gh pr diff <n>` (server-side merge-base, shallow-immune); first publish → two-dot `git diff <base>..<branch>`. `git apply --3way`, commit, move `refs/heads/<branch>` by compare-and-swap (`update-ref <new> <old>`). The replay squashes the branch into one commit — acceptable, the PR merge is `--squash` anyway.
- DECIDED — ON CONFLICT: a failed 3way apply is an ATTENTION state, never `REQUEST_CHANGES` and never auto-resolved: fail the run with `TridentRebaseConflict` whose reason starts `REBASE CONFLICT — needs attention:` naming branch, base, and the conflicting paths, stating no reviewer judged the code. The `resolve_conflict` Forge resolver is NEVER invoked on this path.
