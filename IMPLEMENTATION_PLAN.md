# IMPLEMENTATION_PLAN — Credentials orphaned by a changed owner handle: migrate at boot, and stop calling it "not connected" (card 2026-08-14)

Governing spec: this Plan card (owner-approved design 2026-08-14 — unambiguous ⇒ auto-migrate + audit; ambiguous ⇒ touch nothing, surface `orphaned` + a migrate action; NEVER refuse boot). Verified against main 2026-08-14; T1 landed on `trident/credentials-orphaned-by-a-changed-o` @ 30a65ed:

- The #451 rename reconciler (`migrations/scope-rekey.ts`, wired at `gateway/index.ts:283-342`) already sweeps `secrets.project_slug` and `project_credentials.owner_slug` — but ONLY when the `instance_scope_ledger` disagrees with the boot slug. On this box the ledger was seeded as the boot slug at first boot, so rows written pre-provisioning under `dev` are invisible to it forever: the every-boot path is a single SELECT noop. Nothing in the tree detects credential rows scoped to a non-boot handle when the ledger agrees. This is the gap the card names.
- `SHARED_KEY_ENCRYPTED_TABLES` (`auth/secrets-store.ts:79`) = `['secrets', 'project_credentials']`; scope columns are `secrets.project_slug` and `project_credentials.owner_slug`. `api_keys.project_slug` is the metadata twin the BYO-key read path keys off (`gateway/cores/integrations.ts:120-133`) — T1 sweeps it as a companion table.
- `buildIntegrationsStatus` (`gateway/cores/integrations.ts:262`) and `integrations_list` (`gateway/cores/integrations-tools.ts:79`) report presence-only (`connected: false`) — a wrong-scope miss and "never connected" are still the same sentence. No orphan concept exists yet anywhere in `gateway/cores/`. That is T2, the expensive half of the card.
- Audit precedent: boot journals `credential_scope_migrated` / `credential_scope_orphaned` through `SystemEventsStore` (`persistence/system-events.ts`, wired `gateway/index.ts:345-408` on the branch).
