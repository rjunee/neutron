# IMPLEMENTATION_PLAN — Derive inline activity from evidence (Plan card, owner-approved 2026-08-14)

Governing spec: this Plan card. **NOT a gate** — nothing here may block, deny, or delay any tool call (the PreToolUse-gate plan is cancelled; this salvages Part 3 alone). Verified against the tree 2026-08-14:

- The EMITTER side exists and needs no work: `runtime/adapters/claude-code/persistent/hooks/activity-tap.ts` POSTs every Pre/PostToolUse to the sink's `/activity` route; the composer's `wiredActivityTap` (`open/composer.ts:3997-4016`) records each row into the in-process `ActivityInspector` keyed by `inspectorScopeKey(project_id)` — with the two-clock design where `last_real_activity_at` EXCLUDES synthetic keepalives (`open/activity-inspector.ts:313`, the ISSUES #386 lesson). Every tool call is already observed, per project scope, in the same process that serves the board.
- The CONSUMER side does not exist: `deriveInlineActive` / `lastRealActivityAt` appear nowhere. `inline_active` is a stored flag read RAW at every boundary: rail (`scanItemsForRailSignals`, `open/project-rail.ts:91-98`, called at `open/composer.ts:2242`), WS `work_board_changed` frame (`open/composer.ts:3676`), HTTP list/reorder (`gateway/http/work-board-surface.ts:224,493`), per-turn fragment (`work-board/fragment.ts:59`), and both clients' dot/`canPlay` (`app/lib/work-board-helpers.ts:250,288`; `landing/chat-react/WorkBoardTab.tsx:120,211`). The web `canPlay` comment names this card's fix outright: "Acceptable until an inline heartbeat/reconciler lands."
- DESIGN DECISION (state in the PR): derive SERVER-SIDE at the read/serialization boundaries so both clients, the pane counters, and the fragment inherit the truth with ZERO client changes — the wire field `inline_active` becomes the derived value; the stored column stays as the hint. Evidence tier is **tier 1 only** (inspector clocks — an O(1) in-memory Map read per project scope). Tiers 2-3 (branch commits, dirty worktree) shell out per row per render and are EXCLUDED from the read path by acceptance (e); the module doc records them as deliberate non-goals. Freshness window 90 s, aligned with `WEDGE_AFTER_MS` (a session with no real activity for 90 s is not visibly working). Restart semantics are free and correct: the inspector buffer dies with the process, so after a crash/redeploy evidence reads 0 and every stale flag reads NOT active — acceptance (b) by construction.
