# IMPLEMENTATION_PLAN — A build must rebase onto main before review (stale branch ≠ rejected build)

Governing spec: this Plan card. Verified against main 2026-08-14 (`d8324cc`):

- The readiness probe is repaired and honest: `classifyReviewReadiness` (`trident/inner-workflow.mjs:2123`) reads `mergeable: CONFLICTING` and defers the review round. Correct behavior, now exposing that NOTHING rebases a pr-mode branch — the comment at `trident/orchestrator.ts:479` claims "THE BUILD REBASES ONTO CURRENT main" but no code does; the only rebase machinery in the tree is local-mode merge-time (`merge.ts` + `conflict-resolver.ts`).
- The lease push already exists and is correct: `publishBuiltCommit` (`orchestrator.ts:465-553`) pins `--force-with-lease=refs/heads/<b>:<sha>` to an `ls-remote`-OBSERVED sha, never the remote-tracking ref; third-party-advance refusal is asserted (`orchestrator.test.ts:273-298`). Acceptance (c)'s mechanism is DONE at the fake-host level; the rebase must reuse this exact push, and (c) still needs a REAL-remote assertion (T2).
- DECIDED — WHEN: the rebase lives in the OUTER publisher, between the local-tip verification and the lease observation/push. Only the outer loop holds a push credential (the Forge sandbox strips `*TOKEN*`), so "rebase + re-push before the readiness probe" can only happen there; and because the publisher fires after EVERY build/fix round and before EVERY review re-fire, every fix round re-enters a branch already based on current main — post-round-1 code IS written against the tree it merges into, the closest to "before build" the credential boundary allows.
- DECIDED — MECHANISM (shallow-safe, governance #574/#571): never `git rebase` in the shared checkout (`.git/shallow` boundary makes merge-base lie). Replay the branch's own diff onto the OBSERVED base tip in a throwaway detached worktree: PR exists → `gh pr diff <n>` (server-side merge-base, shallow-immune); first publish → two-dot `git diff <base>..<branch>` against the local base ref the branch was cut from. `git apply --3way`, commit, move `refs/heads/<branch>` by compare-and-swap (`update-ref new old`). The replay squashes the branch into one commit — acceptable, the PR merge is `--squash` anyway.
- DECIDED — ON CONFLICT: a failed 3way apply is an ATTENTION state, never `REQUEST_CHANGES` and never auto-resolved: fail the run with a reason that starts `REBASE CONFLICT — needs attention:` naming branch, base, and the conflicting paths (`diff --name-only --diff-filter=U` in the scratch worktree), stating no reviewer judged the code. The `resolve_conflict` Forge resolver is NEVER invoked on this path (it belongs to local-mode merges).
