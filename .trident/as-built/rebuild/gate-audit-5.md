### Conflict details

**G057 — inventory line `docs/trident-gates-inventory.md:131`.** Property: “Enabled core review seats need usable verdicts; a missing seat contributes a blocker.” The rebuilt panel instead returns `unknown` for a missing observation or unusable verdict (`trident/gates/review-panel.ts:81-85`), which the host maps to the nonterminal unknown outcome (`trident/build-run.ts:123`, `trident/build-run.ts:352-355`). Lost: an incomplete required panel is no longer classified as a blocking refusal, so callers see uncertainty rather than the inventory's blocker.

**G060 — inventory line `docs/trident-gates-inventory.md:134`.** Property: “Missing or unusable synthesis, including a thrown review round, becomes an infrastructure block rather than approval.” The rebuilt panel returns `unknown` for absent or unusable synthesis and for a thrown observation (`trident/gates/review-panel.ts:88-91`, `trident/gates/review-panel.ts:113`), and the host preserves unknown rather than converting it to blocked (`trident/build-run.ts:352-355`). Lost: synthesis failure no longer enters the infrastructure-block outcome expected by the inventory.

**G084 — inventory line `docs/trident-gates-inventory.md:168`.** Property: “A fix-round reviewed-head pin must be full width and the produced head must descend from it before publishing.” The rebuilt host captures `options.reviewed_head` once and uses that unchanged value only at publication (`trident/build-host.ts:20-34`, `trident/build-host.ts:123-130`), while the driver can execute multiple fixes in one call (`trident/build-run.ts:348-380`) and a null captured value bypasses ancestry (`trident/gates/fix-lineage.ts:8-15`). Lost: fresh runs with in-process fix rounds can publish a produced head without proving descent from the head that the immediately preceding review examined.

### Outcome vocabulary and defaults

The panel joins the existing `ReviewDecision` vocabulary: `approve`, `fix`, `re-plan`, `blocked`, and `unknown` (`trident/build-run.ts:29-34`). The host maps `blocked` to a terminal orchestrator-addressed block and maps `unknown` to a nonterminal outcome retaining phase and step identity (`trident/build-run.ts:115-123`, `trident/build-run.ts:150-156`, `trident/build-run.ts:352-355`). `reviewPanel` defaults missing/malformed observations and synthesis to `unknown`, non-completed configured seats and unresolved empty verdicts to `blocked`, blocker/major findings to `fix`, an eligible first design gap to `re-plan`, and a checkpointed clean/advisory panel to `approve` (`trident/gates/review-panel.ts:63-113`). These distinct defaults are why G057 and G060 conflict even though neither path approves.

G084's invariant is maintained only when a nonnull pin reaches `fixLineage`, which validates width and delegates ancestry to git (`trident/gates/fix-lineage.ts:8-22`). No continuous maintainer updates the constructor-captured pin after each in-process review: the positive-controlled `reviewed_head` search finds the host field and its final use (`trident/build-host.ts:33`, `trident/build-host.ts:129`) but no assignment in the fix loop (`trident/build-run.ts:348-380`). The mechanism therefore depends on an outer caller starting a new host with a persisted pin, which the in-process path does not do.
