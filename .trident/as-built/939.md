## 2026-09-15 — Configured cross-model review seats (#939)

### Change and evidence

Additional reviewers are rows in `NEUTRON_REVIEW_SEATS`, resolved on each registry read
(`trident/model-tiers.ts:238`). Each row requires `tier`, `provider`, `model`, `endpoint`
(the complete chat-completions URL), and `credential` (an environment variable name).
Provider names and credential references are strings (`trident/model-tiers.ts:60`,
`trident/model-tiers.ts:79`). Select a row's tier through `review_codex.model` or
`review_kimi.model`; both phases accept the shared API executor
(`trident/phase-models.ts:257`, `trident/phase-models.ts:268`).

The API executor sends the exact configured model and endpoint, reads the referenced
credential at invocation, rejects redirects, and refuses a different or missing response
model (`trident/api-review.ts:19`, `trident/api-review.ts:24`, `trident/api-review.ts:36`).
The CLI reports successful review text or blocking exit 3
(`trident/api-review-cli.ts:7`, `trident/api-review-cli.ts:11`).

The launcher sends credential availability, never the credential value
(`trident/inner-loop.ts:765`). Missing credentials and unknown selected tiers become
named deferred seats before any review agent is invoked
(`trident/inner-workflow.mjs:561`, `trident/inner-workflow.mjs:563`,
`trident/inner-workflow.mjs:5311`, `trident/inner-workflow.mjs:5326`). Retries preserve
that refusal (`trident/inner-workflow.mjs:5371`). Explicitly selected built-in seats
also refuse missing credentials (`trident/inner-workflow.mjs:564`).

Two registry consumers needed corrections to complete this path: settings now measure
the configured credential, rather than treating it as Kimi
(`gateway/http/trident-phase-models-surface.ts:168`), and the build read preserves
retired peer selections rather than discarding them
(`gateway/storage/owner-metadata.ts:127`, `trident/inner-loop.ts:784`).
The regression writes a valid configured selection, removes its registry row, and checks
that the build still receives the selected name
(`gateway/__tests__/trident-phase-models-producer.test.ts:501`).

### Decisions and outcome vocabulary

- Configuration extends the existing registry; built-in defaults and Kimi's wrapper
  remain the default rows (`trident/model-tiers.ts:192`). The existing Kimi suite passed.
- Executor groups describe supported protocols, not an enum of model providers. One
  `api` group supports arbitrary configured providers without another dispatch branch
  (`trident/model-tiers.ts:69`, `trident/model-tiers.ts:262`). New wire protocols would
  still require implementation. This lane supports OpenAI-compatible chat completions.
- Refusals join the existing `CrossModelStatus` value `deferred`, not the permissive
  `not_connected` value (`trident/kimi-review.ts:103`). The bridge uses the existing
  `codexStatus` schema field (`trident/inner-workflow.mjs:5174`). The existing gate
  forces REQUEST_CHANGES and injects blockers (`trident/inner-workflow.mjs:2512`);
  the API group uses its generic deferred branch, now naming the model and refusal
  (`trident/inner-workflow.mjs:5071`, `trident/inner-workflow.mjs:5089`).
- The workflow maintains panel membership and refuses locally on missing credentials;
  this does not depend on the unavailable provider or review agent still working.
  The invoked CLI rechecks the credential (`trident/api-review.ts:20`).
- Response model identity is exact. A provider that omits it or substitutes an alias
  is refused; configure the actual response identifier (`trident/api-review.ts:36`).
- No direct-chat work, substrate selector changes, provider-specific onboarding,
  arbitrary additional panel slots, or live-provider verification was attempted.
  No product decision in SPEC.md was changed. The as-built staging destination follows
  this lane's explicit instruction.
