## 2026-08-31 — The build loop runs the purity gate on its own branch before opening a PR

Measured 2026-08-31: three of four freshly opened build PRs were red, all on
the same single required check — `scripts/ci/leak-gate.sh` — and every finding
sat in the branch's own plan doc under `.trident/plans/`. The builder's prose
about the gate used the gate's own banned vocabulary, so a note asserting
compliance was itself the violation. That prose is regenerated by a model every
run; no one-off rewording could hold, so the fix had to be mechanical.

The outer publisher now runs the gate itself before any PR opens.
`publishBuiltCommit` (`trident/orchestrator.ts`) invokes the real gate over a
throwaway detached worktree of the built branch between the rebase replay and
the lease push (`trident/leak-preflight.ts`). A finding becomes work, not a red
PR: one bounded ephemeral reword turn (`trident/leak-fixer.ts`, wired as the
orchestrator's `fix_leak_findings` seam in `open/composer.ts`) corrects the
flagged text in place and commits, the preflight re-runs, and the new head
propagates by compare-and-swap to the push, the confirm and the review diff. At
most two fix attempts, then the PR opens anyway with the findings named as
`[rule] file:line` — never the excerpt, and only after the annotation passes a
sanitizer, because the vocabulary rule ids contain the banned root and an
unsanitized quote of gate output would re-trigger the very gate it reports.
Every preflight status proceeds to publish; only the fix loop is bounded work,
so a gate bug can never wedge a lane silently.

Degradation is honest. Without the PII denylist secret the preflight still runs
the tiers that need no secret and reports the skipped tiers by name as
INCOMPLETE — a tier that could not run never reads as passing, because an empty
scan reading clean is the exact failure mode that shipped the defect.
`trident/leak-preflight-realgit.test.ts` pins both verdict directions against
the real gate binary over a real throwaway repo: a seeded plan doc is detected
at its exact line, a clean doc passes, skipped tiers are named, and a real
fixer round terminates, commits and advances the branch ref onto a child of the
old head.

Review found the first cut had run the SCANNED CHECKOUT's own copy of the gate
— and that script in turn executes files beside it — under a runner whose
environment carries the owner's GitHub credential, before the PR opened and
before any reviewer saw the diff. Two independent controls now, the pairing the
merge-driver docblock in `trident/orchestrator.ts` arrived at after the same
mistake twice: `ownLeakGateScript()` resolves THIS installation's gate by
walking up from the module, so nothing the branch ships is ever executed, and
the command is prefixed with `env -u` over the credential plus the three
GitHub-runner variables that would otherwise flip the gate into its
canonical-secret context and make the preflight permanently inert. The gate
needs none of it: every git read it makes is local. A branch that rewrites the
scanner is pinned as a test — its sabotaged copy would leave a marker file and
report silent, and neither happens.

Three smaller corrections in the same round. The fixer's staged work is audited
against the index rather than counted: an in-place modification of exactly the
files the gate flagged, never a deletion, never the scanner or its allowlist —
so "fix the text, not the scanner" is a check and not only a sentence in a
prompt. A verdict whose tiers could not all run now says INCOMPLETE even when a
reword landed, because `fixed` is a passing word. And a failed body edit on a
freshly minted PR falls back to the comment path instead of consuming the
annotation, so unresolved findings cannot end up in a log line and nowhere else.
The reword turn also runs on its own substrate profile, `PROFILE_LEAK_FIXER`,
which is the ephemeral build profile minus the GitHub grant: it commits nothing
and pushes nothing, so it carries nothing that publishes.
