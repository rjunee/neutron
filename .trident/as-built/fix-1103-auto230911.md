## Issue 1103 — provider-selected project acting turn

### What changed

`open/wiring/project-build.ts:235-241` now selects the persistent Codex acting turn when the project conversation provider is `openai-codex`. The composition opens `CodexProjectSessionHost` with the project directory and the shared Codex environment at `open/wiring/project-build.ts:227-237`, grants the assigned build worktree at `open/wiring/project-build.ts:238-240`, and leaves the existing Claude session path as the `anthropic` arm at `open/wiring/project-build.ts:243-301`.

The Codex environment is built once at `open/wiring/project-build.ts:230` and is shared by the persistent acting turn at `open/wiring/project-build.ts:237` and the headless runner at `open/wiring/project-build.ts:309`, including a run-specific `CODEX_HOME` when supplied.

`runtime/adapters/select-substrate.ts:22-25` now records that its conversational/headless substrate factory and the project build's persistent acting-turn selector are separate composition seams.

### Evidence and acceptance

The project-level regression enters through the captured `createProjectRunners` composition at `open/__tests__/project-build-wiring.test.ts:192-221`. Its fake persistent host renders an approval after the dispatch submission at `open/__tests__/project-build-wiring.test.ts:197-208`; the assertions require the refusal taxonomy, exactly two acknowledged submissions, the bracketed-paste denial key, and the configured Codex environment at `open/__tests__/project-build-wiring.test.ts:224-231`.

The new outcome joins the existing acting-turn vocabulary in `runtime/workers/project-runners.ts:24-31`: `turn-ended`, `unknown`, or `refused`. The Codex adapter classifies an out-of-grant approval as `refused` at `runtime/workers/codex-acting-turn.ts:51-59`; the project runner preserves that classification at `runtime/workers/project-runners.ts:133-146`. No new default outcome was introduced.

The durable session invariant is maintained by `CodexProjectSessionHost.open`, which deduplicates openings by project id at `runtime/adapters/codex-cli/persistent/project-session.ts:192-201`, records the restart-survival pane handle at `runtime/adapters/codex-cli/persistent/project-session.ts:244-257`, and defaults to `HerdrHost` at `runtime/adapters/codex-cli/persistent/project-session.ts:187-190`. This mechanism observes and records the host handle rather than relying on the acting worker to report continuity.

### Decisions

The Codex host is constructed once per prepared project build, outside the acting-turn callback (`open/wiring/project-build.ts:227-230`), so repeated role turns reuse the host's project-id opening. The registry is shared under the build state root rather than the per-run state directory (`open/wiring/project-build.ts:224-229`), preserving project conversation recovery across runs.

The binding uses the project directory as the persistent session working directory and adds the assigned worktree as an explicit grant (`open/wiring/project-build.ts:236-240`). This keeps the long-lived conversation project-scoped while allowing the bounded request's generated worktree.
