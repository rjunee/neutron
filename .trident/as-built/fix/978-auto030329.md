### Decisions and limits

Canonicalize directory aliases rather than rejecting equivalent spellings; the
positive recovery fixture is
`runtime/adapters/codex-cli/persistent/project-session.test.ts:172`.
A live legacy record without directory evidence reports recovery **unknown**;
a known different directory reports **refused**. These join the existing string
error vocabulary used for unavailable inspection and identity mismatch
(`runtime/adapters/codex-cli/persistent/project-session.ts:233`,
`runtime/adapters/codex-cli/persistent/project-session.ts:244`). No new tagged
outcome or fallback is introduced. Existing legacy panes must be positively
reported gone before replacement can establish a new binding
(`runtime/adapters/codex-cli/persistent/project-session.ts:249`). Do not erase a
live record to bypass this check.

The downstream default is material: `open/wiring/project-build.ts:247` awaits the
session without translating its errors into an acting-turn observation, and
`runtime/workers/codex-in-repl.ts:97` maps thrown dispatch errors to generic
unknown. This change preserves the session API's distinct diagnostics; it does
not claim the worker exposes that distinction. Worker changes are explicitly
outside this lane.

The maintained invariant is the **requested launch directory binding**, checked
on every open and carried across gateway restarts by the registry; it does not
require the old gateway to remain alive. It does not measure the live process's
current directory or defend against external registry edits, directory inode
replacement, or multiple independent registry writers. The host inspection
vocabulary exposes argv but not cwd
(`runtime/adapters/claude-code/persistent/pty-host.ts:438`).
