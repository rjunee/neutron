## Issue 569 — linked plan titles

### Built

Linked active-card titles now open their plan through the same callback as the adjacent document control; cards without an in-app document reference retain inline title editing (`landing/chat-react/WorkBoardTab.tsx:1175`). Linked titles in the Shelved and Done disclosures also open their plans (`landing/chat-react/WorkBoardTab.tsx:939`, `landing/chat-react/WorkBoardTab.tsx:991`).

Successful document writes now fan out through the existing mutation hook to both comment re-anchoring and plan-title synchronization, with `Promise.allSettled` ensuring either consumer still runs if the other fails (`open/composer.ts:3662-3671`). The service reads the written document from its document project, extracts the first ATX H1 after frontmatter, enumerates the target board with `list`, and updates every card whose exact `design_doc_ref` identifies that path (`work-board/spec-doc-service.ts:108-136`, `work-board/spec-doc-service.ts:252-261`). General keeps its distinct document-project and board-scope identifiers (`open/composer.ts:4396-4401`).

### Decisions

The document H1 is authoritative because generated plan documents already place the card title there (`work-board/spec-doc.ts:202-220`). A missing H1, an unrelated document, or a read failure is a no-op; failures join the service's existing structured warning vocabulary and do not turn a successful document save into an HTTP error (`work-board/spec-doc-service.ts:113-135`). No new client/server outcome value was introduced.

The post-write callback maintains the synchronization continuously. It is invoked only after a file mutation lands (`gateway/http/doc-store.ts:431-445`), and independent settled promises prevent the existing comment walker from disabling title synchronization or vice versa (`open/composer.ts:3666-3670`).
