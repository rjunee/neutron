## 2026-09-15 — recognizer inventory fails when a marker selects nothing

### What changed

The recognizer inventory is now materialized before per-site tests are registered (`trident/run-head-width.test.ts:37-44`). It counts selections containing an executable regex and calculates the tests that the inventory can generate (`trident/run-head-width.test.ts:45-46`). Two top-level tests pin the expected 21 recognizer sites and 231 generated recognizer assertions (`trident/run-head-width.test.ts:48-54`).

The per-marker positive control remains (`trident/run-head-width.test.ts:56-61`). A marker with no selected regex now stops only that marker's behavioral-test registration (`trident/run-head-width.test.ts:62`), so the top-level expectations execute and identify the incomplete inventory instead of test-file evaluation dereferencing a missing match.

The complete site list was enumerated from the `sites` object at `trident/run-head-width.test.ts:11-34`: its marker arrays contain 21 entries across eight source files. Each selected site registers one positive control, two accepted-width cases, six refused-width cases, and two refused-non-hex cases at `trident/run-head-width.test.ts:58-74`, totaling 11 tests per site.

### Decisions and classification

The fixed totals are intentionally independent of the marker strings. Computing the expected count from the current marker arrays would let deletion weaken the guard. Inventory construction is shared by both the totals and per-site behavior so the count describes the tests actually reachable from the current source selection (`trident/run-head-width.test.ts:37-46`).

The new outcome joins Bun's existing pass/fail expectation vocabulary: both guards use ordinary `expect(...).toBe(...)` assertions (`trident/run-head-width.test.ts:48-54`), whose default for a mismatch is a named failed test. The invariant is maintained continuously by the focused test file itself; the repository runner discovers test files and treats any failing test as exit 1 (`scripts/run-tests.sh:19-25`, `scripts/run-tests.sh:132-135`), independently of the production recognizer being checked.
