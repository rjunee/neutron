## Issue 1043 — adopted branches record their actual base

### What changed

A fresh PR launch still fetches and resolves the current remote base before inspecting the local build branch (`trident/launch-preparation.ts:260-336`). When that branch already exists and the existing ancestry vocabulary returns `yes`, the launcher now records the branch tip as the proven merge-base and recomputes `base_behind` from that same commit to the fetched base (`trident/launch-preparation.ts:551-593`). The `unknown` arm remains a fail-closed refusal (`trident/launch-preparation.ts:560-571`), and `no` continues through the existing ownership/refusal path (`trident/launch-preparation.ts:595-689`); this change adds no error, verdict, or default outcome.

The durable pin and workflow input are sourced from the same updated launch record (`trident/launch-preparation.ts:591-593`, `trident/orchestrator.ts:1974-1978`). This maintains the invariant at launch without depending on the earlier failed run. Current comments and the publication refusal now describe `base_sha` as the recorded cut point rather than always the newest remote tip (`trident/merge.ts:448-456`, `trident/publication.ts:141-150`).

The measured-diff implementation remains three-dot (`trident/production-host-effects.ts:203-210`), and its test now asserts the exact three-dot range (`trident/production-host-effects.test.ts:160-169`).
