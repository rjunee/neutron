## 2026-09-16 — remove unreachable review-suite deferred acceptance

### What changed

Removed the subset-only `suiteOutcome === 'deferred'` acceptance from
`trident/gates/review-suite.ts`. It sat AFTER the line requiring a numeric
`hostExitCode`, and a subset render never produces one, so it could not be reached.

What the gate decides now, stated as its full table rather than a summary that a
reviewer can find a counterexample to (three successive drafts of this paragraph
each overclaimed a different case):

| input | result | where |
|---|---|---|
| `strategy === ''` | **known, no findings** — no strategy means nothing to prove; receipt not consulted | `review-suite.ts:39` |
| receipt missing, or `hostExitCode` not an integer | **unknown** | `:41` |
| `hostExitCode === 0` | **known, no findings** | `:43` |

| nonzero + `failed-preexisting` WITH evidence | **advisory** — an approving panel stands; the human verifies the base comparison | `:47` |
| any other nonzero (`deferred` included, any scope) | **blocker** `FULL SUITE NOT PROVEN` | `:49` |

The test at `trident/gates/review-suite.test.ts:12` drives every row, including the
evidenced advisory case in both directions (it previously skipped
`failed-preexisting` entirely). The G063 inventory row at
`docs/trident-gates-inventory.md:137` states the same table in prose.

### Decision and evidence

(Corrected after review: the record previously attributed line citations to "the
filed issue".) The unreachable condition sat at `trident/gates/review-suite.ts:44`
before this change; the required numeric receipt remained at line 41. The project

it was deliberately not changed.
