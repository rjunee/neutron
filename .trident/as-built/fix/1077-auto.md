### Decisions and limits

Simple shebangs are supported; interpreter options refuse explicitly (`runtime/adapters/codex-cli/persistent/project-session.ts:82`) rather than being silently discarded. This is filesystem path identity, not content attestation: replacing bytes at the same real path is outside this change. Shell wrappers that exec some other command are not interpreted. No live herdr process was exercised.

The existing result vocabulary is `CodexSessionRecovery` (`runtime/adapters/codex-cli/persistent/project-session.ts:11`): started, adopted, restarted-after-loss. Resolution and identity errors use the existing thrown refusal behavior (`:181`, `:202`), not a new success state. The existing rejection handler clears the pending open and rethrows (`:168`); its default is failure, not adoption or replacement.

This is an adoption-time invariant maintained on every uncached open by inspection and comparison (`runtime/adapters/codex-cli/persistent/project-session.ts:195`). It does not depend on the observed pane cooperating. Already-open sessions are cached (`:166`); continuous executable monitoring is deliberately outside scope. No product decision changed, and no feature flag, fallback basename matcher, or additional runtime name allowlist was introduced.
