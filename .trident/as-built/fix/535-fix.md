## Issue 535 — Surface infrastructure retries to the owner

### What changed

Production now supplies the first-retry callback beside the durable retry claim at `gateway/composition/build-core-modules.ts:825-827`. The callback uses the run's persisted channel routing through `deliverInfraRetry`, which skips rows without an originating chat and sends the attempt plus measured cause at `trident/delivery.ts:1450-1465`.

`RunProgress` now carries the durable count at `trident/run-progress.ts:60-73`, and its derivation selects `retrying` only for a nonterminal run with at least one claimed retry at `trident/run-progress.ts:220-228`. The existing step-label vocabulary gained `retrying`; mobile renders it as a live build-colored “Retrying” tag and “attempt N” at `app/lib/work-board-helpers.ts:224-238` and `app/lib/work-board-helpers.ts:341-347`. The web twin implements the same mapping at `landing/chat-react/WorkBoardTab.tsx:220-236` and `landing/chat-react/WorkBoardTab.tsx:328-334`.

### Decisions

The durable store counter remains the single source of truth. It is already incremented atomically by the retry claim, and the wire derives display state from that persisted value, so process restart cannot erase the attempt count (`trident/store.ts:1540-1551`, `trident/run-progress.ts:224-228`).

The new `retrying` outcome joins `RunStepLabel`, whose switches choose card tag, dot color, pulse, and secondary count. Its client fallback remains the existing phase-derived label when an older frame lacks the new member (`app/lib/work-board-client.ts:352-396`). Exhaustion does not use `retrying`: terminal phases bypass it and retain the failed outcome (`trident/run-progress.ts:224-226`), while the budget test requires the recorded failed phase and budget reason (`trident/infra-retry.test.ts:222-234`).

Notification remains best-effort. The orchestrator catches callback failures after the durable claim, so the visibility transport cannot keep a dead run alive or stop the retry (`trident/orchestrator.ts:5157-5167`). Its durable-attempt-one condition provides once-per-run behavior independently of process memory (`trident/orchestrator.ts:5157`).
