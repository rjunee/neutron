### What changed

Production now supplies the first-retry callback beside the durable retry claim at `gateway/composition/build-core-modules.ts:826-830`. The callback uses the run's persisted channel routing through `deliverInfraRetry`, which skips rows without an originating chat and sends the attempt plus measured cause at `trident/delivery.ts:1450-1465`.

`RunProgress` now carries the durable retry count beside the outer and inner build counters and the shipped heartbeat at `trident/run-progress.ts:60-83`; its derivation selects `retrying` only for a nonterminal run with at least one claimed retry and emits all three measurements together at `trident/run-progress.ts:228-243`. Both client decoders retain the retry count, outer counter, and heartbeat with rolling-frame defaults at `app/lib/work-board-client.ts:420-433` and `landing/chat-react/work-board-client.ts:475-485`.

The counter remains #917's one-based outer task plus inner review form at `app/lib/work-board-helpers.ts:343-348` and `landing/chat-react/WorkBoardTab.tsx:321-326`. Retry state cannot make a dead run look alive: its dot asks the same heartbeat-backed `isLinkedRunning` predicate on mobile and web at `app/lib/work-board-helpers.ts:319-320,358-366` and `landing/chat-react/WorkBoardTab.tsx:300-301`.

### Decisions

The durable store counter remains the single source of truth. It is already incremented atomically by the retry claim, and the wire derives display state from that persisted value, so process restart cannot erase the attempt count (`trident/store.ts:1540-1551`, `trident/run-progress.ts:224-228`).

The new `retrying` outcome joins `RunStepLabel`, whose switches choose card tag and dot color; an unknown wire value still falls back to the existing phase-derived label at `app/lib/work-board-client.ts:411-420`. Its default pulse is false unless the linked run has an unexpired wrapper heartbeat at `app/lib/work-board-helpers.ts:319-320,358-366`. Exhaustion does not use `retrying`: terminal phases bypass it and retain the failed outcome (`trident/run-progress.ts:232-234`), while the budget test requires the recorded failed phase and budget reason (`trident/infra-retry.test.ts:222-234`).

Notification remains best-effort. The orchestrator catches callback failures after the durable claim, so the visibility transport cannot keep a dead run alive or stop the retry (`trident/orchestrator.ts:5157-5167`). Its durable-attempt-one condition provides once-per-run behavior independently of process memory (`trident/orchestrator.ts:5157`).
