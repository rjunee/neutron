## Issue 558 — merge gate requires a verdict for the pull-request head

### What changed

The required CI rollup now depends on a `trident-verdict` job that receives the pull request's head SHA and runs the gate (`.github/workflows/ci.yml:443-505`). The gate accepts only a visible, trusted, clean review record for the full head commit, and a new commit therefore invalidates an older record (`scripts/ci/trident-verdict.ts:10-20,103-130,1242-1254`). It fails closed when configuration or API data cannot be read (`scripts/ci/trident-verdict.ts:1006-1020`) and prints a branch-preserving recovery route on refusals (`scripts/ci/trident-verdict.ts:22-28,1243-1247`).

Comment creation, editing, or deletion re-runs the whole matching CI run so the newest review record can grant or withdraw the result (`.github/workflows/trident-verdict-rerun.yml:18-38,155-172`). The pre-push hook remains advisory and derives commands from the refs actually being pushed (`.githooks/pre-push:43-52,148-152`).

The outcome vocabulary is the existing process exit contract: `0` is accepted and `1` is refusal (`scripts/ci/trident-verdict.ts:1242-1254,1291-1296`). Unknown, malformed, unreadable, absent, stale, and blocking states all default to refusal; only an exact accepted record or explicitly recorded bypass returns success (`scripts/ci/trident-verdict.ts:1108-1147,1200-1254`). The required `test` aggregator treats any verdict-job result other than `success` as failure on pull-request events (`.github/workflows/ci.yml:499-504`).

### Decisions

The reviewed implementation named by the filed issue was adopted from its final local commit, then reconciled with the current tree's eight-shard workflow and SHA-pinned-action guard. The legacy shared as-built log was deliberately not restored because it is frozen; this issue's record is this dedicated shard. No feature flag or alternate gate path was added.

The invariant is maintained continuously by the required CI aggregator, not by the author whose change is being checked (`.github/workflows/ci.yml:469-504`). Comment changes trigger a fresh read from the default-branch workflow, so withdrawal does not depend on the original build process remaining alive (`.github/workflows/trident-verdict-rerun.yml:18-35,126-172`).
