## 2026-09-16 — Codex hosted session submission framing (#978)

### Scope

This branch does ONE thing: it frames a submitted line as a completed bracketed
paste, and refuses a payload that could break out of that frame.

It no longer carries any pane-identity change. An earlier revision did, and it
was dropped whole in the rebase onto `69fffe97`: #1082 replaced basename
matching with resolved-path identity (`resolveIdentity` / `matchesIdentity`),
and this branch's `isCodexArgv` would have been a silent semantic revert of it.
Nothing about adoption, interpreter recognition or launcher shapes is decided
here. That is a deliberate removal, not an omission.

This change also does not establish live acceptance of increment 1 or authorize
increment 2.

### What changed

`runtime/adapters/codex-cli/persistent/project-session.ts:139` wraps the text in
bracketed-paste boundaries before the host sends Enter:

```ts
await submit.call(this.child, `\x1b[200~${line}\x1b[201~`)
```

herdr delivers a submitted line to the Codex TUI as ordinary keystrokes, so a
payload carrying control characters could be interpreted as editor input rather
than as submitted text. A completed paste makes the TUI take the whole payload
as one literal insertion. This follows the measured spike in the issue and
avoids a timing-dependent sleep.

`:122` refuses a payload containing a line terminator or escape character:

```ts
throw new Error('codex project session refuses embedded line terminators or escape characters')
```

Without it, a payload carrying the paste terminator `\x1b[201~` would close the
bracket early and leave the remainder to be read as keystrokes — the framing
would create the injection it exists to prevent. Refusing is the correct answer
because the caller's intent is unrecoverable at this layer.

The host acknowledgement contract is unchanged: it means text and Enter were
delivered, NOT that a model turn completed
(`runtime/adapters/claude-code/persistent/pty-host.ts:180`).

### Tests

`runtime/adapters/codex-cli/persistent/project-session.test.ts:334-349`, two

`:273` — main's `two concurrent submissions are serialized` case now asserts the

bytes it observes are what actually reach the pane, so they move with this fix.
