## 2026-09-16 — Codex hosted session submission and adoption corrections (#978)

### Scope and decisions

The latest staged issue comment identifies two bounded defects in the existing
hosted session. This change repairs those defects; it does not establish live
acceptance of increment 1 or authorize increment 2.

`runtime/adapters/codex-cli/persistent/project-session.ts:112` now wraps text in
bracketed-paste boundaries before the host sends Enter. This follows the measured
spike in the issue, avoiding a timing-dependent sleep. The host acknowledgement
still means text and Enter delivery, not model turn completion (contract:
`runtime/adapters/claude-code/persistent/pty-host.ts:180`). Herdr sends the two
acknowledged operations at `runtime/adapters/claude-code/persistent/herdr-host.ts:669`
and `:674`; Bun writes them at
`runtime/adapters/claude-code/persistent/bun-terminal-host.ts:511` and `:512`.

`runtime/adapters/codex-cli/persistent/project-session.ts:66` recognizes an
interpreter only in the executable slot, then checks the script slot and exact
remaining arguments at `:72`. Bare configured names permit resolved executable
paths; explicit configured paths must match exactly (`:69`). The exemplar was
read for that property: `runtime/adapters/claude-code/persistent/orphan-adoption.ts:282`
checks the script slot, not arbitrary later arguments.

Escape input is refused at `runtime/adapters/codex-cli/persistent/project-session.ts:94`
so callers cannot terminate the paste framing. This extends the existing input
refusal Error, whose default behavior is a rejected submit promise before host
actuation (`:95`), rather than adding a new recovery tag. Normal input remains
writable (`runtime/adapters/codex-cli/persistent/project-session.test.ts:206`).
Recovery retains its separate unknown inspection rejection (`project-session.ts:168`)
and known identity refusal (`:172`).

The per-session promise tail continuously orders submission and releases in
finally (`project-session.ts:103`, `:107`, `:114`). The mechanism lives in the
session wrapper and does not depend on Codex implementing a lock or on caller
cooperation. Its scope is concurrent calls through that wrapper, not arbitration
with a human typing in the pane or another gateway instance.
