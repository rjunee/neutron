## Issue 1062 — fence an abandoned herdr dispatch

### What changed

`PtyChild.submitLine` now accepts an optional cancellation signal and defines the
pre-submission fence at `runtime/adapters/claude-code/persistent/pty-host.ts:191-193`.
The Claude acting turn passes its combined caller/budget signal into the operation at
`runtime/workers/claude-acting-turn.ts:40-56` and aborts that signal when its deadline
race ends at `runtime/workers/claude-acting-turn.ts:72-82`.

Herdr checks abandonment on entry, after queueing, and—load-bearing—after the text
acknowledgement but before the submission-bearing Enter at
`runtime/adapters/claude-code/persistent/herdr-host.ts:623-669`. Thus a late
`pane.send_text` acknowledgement cannot resume an operation whose acting turn already
returned. The retained Bun backend implements the same shared pre-submission contract
at `runtime/adapters/claude-code/persistent/bun-terminal-host.ts:495-512`.

The continuous maintainer is the acting turn's host-budget race: its `finally` aborts
the signal independently of whether the pending transport operation returns
(`runtime/workers/claude-acting-turn.ts:72-82`), and Herdr consults that signal before
issuing Enter (`runtime/adapters/claude-code/persistent/herdr-host.ts:663-669`).

The new transport exception is the platform `AbortError`; it does not create a new
bounded-work outcome. The acting-turn vocabulary already contains `turn-ended`,
`unknown`, and `refused` at `runtime/workers/project-runners.ts:24-31`. A host-budget
expiry returns the existing `unknown` at `runtime/workers/claude-acting-turn.ts:40-44`,
and the project runner preserves that uncertainty as `unknown` at
`runtime/workers/project-runners.ts:138-146`; it never shares the refusal branch at
`runtime/workers/project-runners.ts:134-137`.

The acceptance criterion is versioned at
`docs/spec-items/an-abandoned-dispatch-cannot-actuate-later.md:10-19`, and the generated
queue index includes it at `docs/spec-items/README.md:97`.

### Enumeration and decisions

Call sites were mechanically enumerated with
`rg -n 'child\.submitLine|submitLine\(' runtime --glob '*.ts'`. The positive control was
the shared declaration at `runtime/adapters/claude-code/persistent/pty-host.ts:193`;
the production Claude dispatch is at `runtime/workers/claude-acting-turn.ts:53-56`,
while the other matches are the two backend implementations, the shared slash-command
helper, the Codex session adapter, tests, and error text. Only the Claude acting turn
owns the caller give-up race described by this issue, so that caller supplies the
signal. The optional parameter preserves lightweight fakes and unrelated callers while
both real backends honor the shared contract.

Cancellation fences Enter rather than claiming that closing a client connection can
withdraw a request the server already accepted. Herdr types with `pane.send_text` and
submits separately with `pane.send_keys` at
`runtime/adapters/claude-code/persistent/herdr-host.ts:663-669`; preventing the latter
is the enforceable actuation boundary.

The filed issue supplied no repository line citations, so there were no moved line
numbers to correct.

Corrected after review. The first table proved ONE of four guards; a review lane
measured that the other three came out with every test green. Each mutation below

**A fourth guard was removed.** The check ahead of the enqueue (formerly `:631`)
was redundant with the one at the head of the enqueued work: removing either alone
stayed green, removing both went red. Two guards for one property; the enqueued one
also covers abandonment that lands while a prior actuation holds the queue, so it is
the one that stays. The removal is recorded in a comment at the site.

The discriminating fixture holds `pane.send_text`, lets the 20 ms host budget return
`unknown`, then releases the acknowledgement and asserts that Enter was never issued at
`runtime/workers/claude-acting-turn.test.ts:187-207`. Its healthy control proves the
same real host sends text then Enter before abandonment at
`runtime/workers/claude-acting-turn.test.ts:167-185`.

this implements the filed safety criterion without changing the product target.

The original live 33-minute stall and the REPL's exact state during it could not be
reproduced or inspected offline. The test proves the acceptance boundary against the
real `HerdrHost` implementation with a controlled pending acknowledgement; it does not
claim that herdr can retract text already accepted by its server, nor that the original
server delay's internal cause is known.
