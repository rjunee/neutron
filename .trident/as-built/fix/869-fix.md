## 2026-09-15 — Credential-free task prioritization remains deterministic

### What changed

The per-project provider work made the conversational utility substrate constructible whenever a live provider resolver exists, even before any credential is available (`open/wiring/substrates.ts:174-177`). Open composition subsequently treated the substrate's existence as credential availability and built `proactiveLlm` (`open/composer.ts:3384-3388`). On a credential-free boot that gave task prioritization an async LLM function instead of the null value that selects its real deterministic path.

`proactiveLlm` now requires both a constructed substrate and at least one resolved Anthropic or OpenAI credential pool (`open/composer.ts:3384-3388`). This does not choose a provider and does not collapse provider inheritance: the live project/instance selection still resolves independently at `open/composer.ts:1037-1044`. The task cron remains unconditionally enabled at `open/composer.ts:3452`, with the possibly-null LLM passed as data at `open/composer.ts:3455`.

The no-credential composition fixture now saves and clears both credential environment keys (`open/__tests__/open-tasks-wiring.test.ts:42-54`, `open/__tests__/open-tasks-wiring.test.ts:60-73`). It asserts the cron stays enabled and the prioritizer receives null (`open/__tests__/open-tasks-wiring.test.ts:133-146`).

### Decisions and outcome vocabulary

The fix distinguishes three independent facts: a project's explicit selection, a project inheriting the instance selection, and whether the environment has a usable credential. Only the last fact controls whether this background utility receives an LLM function. No unresolved selection is defaulted to a concrete provider.

The existing task-prioritization outcome vocabulary is `PrioritizedBy`, which records `llm` or `deterministic` (`tasks/prioritize-llm.ts:94-100`). Its no-LLM branch writes `prioritized_by: 'deterministic'` and returns that same outcome (`tasks/prioritize-llm.ts:169-178`). Core composition already registers the handler when the enable switch is true and explicitly accepts a null LLM (`gateway/composition/build-core-modules.ts:1324-1355`), so no new outcome or default classification was introduced.

The regression invariant is continuously maintained by the production-composer test at `open/__tests__/open-tasks-wiring.test.ts:133-146`; it does not depend on a provider or credential service being operational because the fixture removes both credential families before composition (`open/__tests__/open-tasks-wiring.test.ts:69-71`).
