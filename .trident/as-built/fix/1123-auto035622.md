## Issue 1123 — step-aware trailer reader

### What changed

The project trailer contract now has a non-terminal `not-current-step` result for a well-formed `run_id` or `step_id` belonging to another request (`runtime/workers/project-runners.ts:41-65`). Missing or malformed identity remains terminal `unknown`, so an unreadable trailer and a stale trailer do not share a signal (`runtime/workers/project-runners.ts:62-66`).

Claude, Codex, and Pi in-REPL runners consume only `not-current-step` by continuing their existing bounded poll loops (`runtime/workers/claude-in-repl.ts:86-95`, `runtime/workers/codex-in-repl.ts:87-96`, `runtime/workers/pi-in-repl.ts:97-106`). The loop deadline and abort signal continuously maintain the invariant that ignoring a stale slot cannot become an unbounded wait. The signal does not enter the build outcome switch: each runner converts only terminal decoder results into its `WorkerRunner` return.

The Claude and Codex acting-turn observers also read the trailer identity before reporting `turn-ended`, while preserving the existing error for a non-file path (`runtime/workers/claude-acting-turn.ts:198-210`, `runtime/workers/codex-acting-turn.ts:70-85`). This prevents the outer observation layer from ending before the step-aware decoder can observe the eventual current trailer.

The complete decode/poll surface was enumerated with `rg -n "decodeTrailer|decodeProjectTrailer|result\\.path|turn-ended" runtime trident --glob '*.{ts,tsx}'` against both the working branch and `origin/main`. As a positive control, the same search found `decodeProjectTrailer` in `runtime/workers/project-runners.ts:59`; it identified all three generic decoder calls at `runtime/workers/claude-in-repl.ts:88`, `runtime/workers/codex-in-repl.ts:89`, and `runtime/workers/pi-in-repl.ts:99`, plus both project acting-turn file observers at `runtime/workers/claude-acting-turn.ts:200` and `runtime/workers/codex-acting-turn.ts:74`.

### Decisions

`not-current-step` is a decoder/reader control signal rather than a `BoundedWorkOutcome`. This keeps it out of the existing terminal outcome vocabulary consumed by `trident/build-run.ts:339-345`, where every value ends or advances the build. Its default handling is explicit at every generic reader: continue polling within the existing budget (`runtime/workers/claude-in-repl.ts:86-95`, `runtime/workers/codex-in-repl.ts:87-96`, `runtime/workers/pi-in-repl.ts:97-106`).

Identity inspection deliberately classifies malformed JSON, non-objects, and missing identity as `current-or-unreadable` at the acting layer (`runtime/workers/project-runners.ts:46-54`). That lets the decoder return the established detailed `unknown` instead of turning corruption into silence (`runtime/workers/project-runners.ts:59-80`). Only two present string identities that differ from the request are stale.

No product decision in `SPEC.md` or an in-repo spec item changed.

### Deliberately not changed and verification limits

The result slot IS still cleared — `reserveTrailerSlot` calls `clearTrailerSlot` on every fresh reservation (`runtime/workers/trailer-slot.ts:85`, unlinking at `:18-26`). This change does not remove that and does not alter writer atomicity, reservations, retry policy, or the dead-owner behaviour excluded by the filed issue. What it adds is an independent second guard: an older valid identity is inert at READ time, so a missed or failed clear can produce a wait rather than a wrong answer. An earlier draft of this section said the slot is not cleared at all; that was false and is corrected here.
