## 2026-09-17 — Preserve concurrent Codex project session recovery records

### Scope and change

Issue #978 increment 1 only. The build worktree already contained the hosted
session, canonical launch identity and terminal paste fixes described in the
later issue comments. This change repairs a remaining restart-record race;
it does not claim that the issue's live acceptance bar is satisfied.

`runtime/adapters/codex-cli/persistent/project-session.ts:225` reads the registry
before asynchronous host operations at :246, :249 and :253. Two different
projects can read the same snapshot, finish spawning in reverse order, and
replace each other's saved pane handle. The fix at :264 rereads the registry
immediately before merging the project record and synchronously writing at :272.
There is no asynchronous gap within that read/merge/write, so other project
opens on the same JavaScript event loop cannot interleave their commits. This
mechanism does not rely on a healthy model process or model cooperation.
It does not establish exclusion between independent gateway processes.

The regression at
`runtime/adapters/codex-cli/persistent/project-session.test.ts:147` holds the
first spawn until the second project has committed. It enumerates the saved
keys at :171, checks both distinct pane handles at :172, then verifies that a
replacement host adopts both without spawning at :175. This is simulated
recovery, not a real gateway-restart observation.

### Decisions and outcome vocabulary

Keep the existing host, transport, identity checks and submission queue. A
synchronous fresh merge is sufficient for the measured event-loop race and
does not serialize slow launches for unrelated projects. No product decision
changed. Recovery still uses the existing `started`, `adopted`, and
`restarted-after-loss` vocabulary at
`runtime/adapters/codex-cli/persistent/project-session.ts:12`. An unavailable
inspection still throws a recovery-unknown error at :232, while mismatched
identity is refused at :242. This change adds no outcome to classify.

The host's acknowledgement contract is delivery of text and Enter, explicitly
not proof the model acted on them:
`runtime/adapters/claude-code/persistent/pty-host.ts:189`.
