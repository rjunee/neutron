Submission wraps text in bracketed-paste start/end bytes before the existing
acknowledged Enter (`project-session.ts:115`, under the directory above). This
implements the remedy measured by the staged spike without a timing delay.
The existing per-session queue remains at `:110`, and release on rejection at
`:116`. Embedded ESC is refused at `:97` so caller text cannot close the paste
frame. The guard runs on every submission, in the host process, independently
of the Codex child's cooperation. Plain text and Unicode remain writable
(`project-session.test.ts:208`); no raw-write fallback is introduced.
Acknowledgement means terminal delivery, not a model answer: the shared contract
states this at `runtime/adapters/claude-code/persistent/pty-host.ts:180`.

Adoption normalizes only a recognized interpreter in argv[0], then checks the
script slot and every launch argument (`project-session.ts:66`). Bare executable
names may resolve to a path; an explicitly configured path stays exact (`:69`).
The exemplar was read first: Claude checks recognized interpreters and ONLY the
script slot in `runtime/adapters/claude-code/persistent/orphan-adoption.ts:282`.
The Codex guard also preserves exact launch flags at `project-session.ts:72` and
the recorded/current configuration comparison at `:174`. It is enforced by the
new host before every adoption, rather than relying on the old gateway surviving.

### Outcome vocabulary and limits

The new escape refusal joins the existing rejecting `submitLine` contract
(`project-session.ts:94`, `:101`, `:112`). Direct callers receive a rejected Error;
there is no successful acknowledgement. The existing worker boundary defaults
unclassified dispatch exceptions to `unknown`, not `refused`
(`runtime/workers/codex-in-repl.ts:97`); structured acting-turn refusals are
handled separately at `runtime/workers/project-runners.ts:134`. This change does
not alter that boundary or claim a new structured worker verdict. Recovery's
existing unknown/refusal distinction remains at `project-session.ts:170` and
`:174`; the recovery vocabulary is `started | adopted | restarted-after-loss`
at `:11`.
