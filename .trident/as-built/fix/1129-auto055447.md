## Issue 1129 — proportionate Ralph rounds

### What changed

The live project composition now gives build and fix workers the generated intermediate strategy when one is present (`open/wiring/project-build.ts:331-358`). Its review-suite source uses the existing `subset` scope and returns the worker's explicit deferred outcome without launching the full-suite child (`open/wiring/project-build.ts:426-454`). The fallback for inputs without an intermediate strategy retains the prior full-suite observation (`open/wiring/project-build.ts:455-464`).

A separate host-owned terminal source parses and runs the full-suite command once into its own transcript (`open/wiring/project-build.ts:468-477`). The project host carries that source independently from per-round review (`trident/project-build-host.ts:84-105`), and the driver refuses to proceed to final publication or merge when terminal evidence is missing, unreadable, or contains a non-advisory finding (`trident/build-run.ts:597-607`).

The outcome joins the existing suite vocabulary: `SuiteObservation.scope` already names `full-suite` and `subset` (`trident/gates/review-suite.ts:12-22`). An explicit deferred subset is known; the same report under full-suite scope remains unknown, a nonzero terminal receipt becomes `FULL SUITE NOT PROVEN`, and an evidenced pre-existing failure retains its existing advisory treatment (`trident/gates/review-suite.ts:31-50`).

### Decisions

The change lands in the live project-REPL path. It does not modify the shared launcher. Intermediate review and terminal verification use two independently configured observation sources so a subset result cannot masquerade as terminal full-suite evidence (`trident/project-build-host.ts:84-105`).

The terminal gate runs after review approval and before the driver can continue to merge or perform a final resumed publication (`trident/build-run.ts:597-610`). Preliminary PR updates still happen before paid review so existing CI readiness remains observable (`trident/build-run.ts:526-545`).

### Measured before and after

Before: the filed production observation was approximately 25 minutes and still running for one review round because each round executed the full repository suite. In the pre-change live wiring, every checkpoint parsed and launched that command.

After: the focused one-file-change fixture completed in 14 ms and observed zero full-suite child launches during the intermediate review, then exactly one launch through the terminal source (`open/__tests__/project-build-wiring.test.ts:132-158`). The complete focused wiring selection took 468 ms for four cases. This is a controlled host fixture, not a claim that the real full suite itself became faster; the saving is removal of its per-round multiplicity.
