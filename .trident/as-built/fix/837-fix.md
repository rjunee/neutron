## Issue #837 — executable hooks cannot arrive silently unlinked

### What changed

The installer now marks its managed directory, records the intentional no-list exclusion for `pre-push`, enumerates every regular executable in `.githooks/`, and links each eligible hook by basename (`scripts/install-git-hooks.sh:57-72`). The existing rule remains intact: without the local pattern source, `pre-push` is excluded while the independent integrity hook is installed (`scripts/install-git-hooks.sh:13-20`, `scripts/install-git-hooks.sh:61-69`, `scripts/install-git-hooks.sh:74-103`).

The installed `pre-commit` hook now enumerates the same executable source set and refuses if the managed entry is absent, is not a symlink, or targets a different file (`.githooks/pre-commit:4-18`). This continuously maintains the new invariant after pulls: the check runs through the already-installed `pre-commit` link and does not depend on the newly added, unlinked hook executing. The new exit `68` joins the hook's existing refusal statuses `65` through `67` (`.githooks/pre-commit:15`, `.githooks/pre-commit:20-37`). Git's existing hook outcome vocabulary treats any nonzero exit as a refusal; no new application-level outcome switch is involved.

The installer header now states the narrower behavior: edits to installed targets arrive immediately, while an unlinked new executable causes a refusal (`scripts/install-git-hooks.sh:8-11`). A tree-wide search used the combined pattern `ln -s .*\.githooks/(pre-commit|pre-push)|for hook_path in .*\.githooks`: its positive controls found both new enumeration loops at `.githooks/pre-commit:7` and `scripts/install-git-hooks.sh:65`, while it found no remaining fixed-name link command. The complete source-hook list was enumerated with `git ls-files .githooks`, which returned `.githooks/pre-commit` and `.githooks/pre-push`.

### Decisions and deliberately excluded work

The managed-directory marker scopes the comparison to directories created by this installer, so a contributor-selected `core.hooksPath` is not reclassified or rewritten (`scripts/install-git-hooks.sh:57-63`, `.githooks/pre-commit:4-6`). The no-list exclusion is a marker beside the links because the checker must preserve the install-time safety decision without assuming a later process environment (`scripts/install-git-hooks.sh:61-63`, `.githooks/pre-commit:10-12`).

This change does not arm `pre-push` without its local pattern source, alter contributor-managed hooks, add a feature flag, or introduce a second installation path. It does not change `SPEC.md`: the filed fix restores installer wiring and makes drift visible without changing a product decision.
