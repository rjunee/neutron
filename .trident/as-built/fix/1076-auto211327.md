## Issue #1076 — `submitLine` frames text as a terminal paste

### What changed

Programmatic line submission now wraps non-empty text in the terminal's bracketed-paste markers through one shared helper (`runtime/adapters/claude-code/persistent/pty-host.ts:66-73`). The Bun backend writes that framed payload before its separately checked Enter (`runtime/adapters/claude-code/persistent/bun-terminal-host.ts:514-522`), and the Herdr backend sends the same framed payload before its separately acknowledged Enter (`runtime/adapters/claude-code/persistent/herdr-host.ts:675-681`). This keeps Enter outside the paste burst, so Codex treats it as submission rather than inserting the burst into the composer.

The invariant is maintained continuously by routing both production `submitLine` implementations through `frameBracketedPaste`. The implementation inventory was enumerated with `rg -n "async submitLine|frameBracketedPaste"` over the two hosts and the shared contract: it found the Bun implementation at `bun-terminal-host.ts:501`, the Herdr implementation at `herdr-host.ts:607`, and helper use at `bun-terminal-host.ts:520` and `herdr-host.ts:676`. Exact framing and ordering are pinned at `bun-terminal-host.test.ts:113-124`, `bun-terminal-host.test.ts:455-479`, `herdr-keys.test.ts:408-426`, and `herdr-keys.test.ts:496-504`.

### Decisions

Bracketed paste was chosen instead of a delay. It encodes the distinction the Codex TUI needs without introducing a timing race. The helper lives on the shared PTY boundary because both supported backends implement the same `submitLine` contract (`runtime/adapters/claude-code/persistent/pty-host.ts:161-193`). Empty submission remains an Enter without an empty paste frame because both implementations already skip their text operation for an empty command (`bun-terminal-host.ts:519-522`, `herdr-host.ts:675-681`).

No new error, verdict, state, or refusal was added, so no outcome taxonomy required extension. Existing partial-delivery behavior remains classified by rejection: Bun rejects a short framed-text or Enter write (`bun-terminal-host.test.ts:455-470`), and Herdr rejects a refused text or Enter RPC (`herdr-keys.test.ts:508-539`). No product decision changed, so `SPEC.md` and the issue's normative scope were not changed.

The issue's cited implementation lines had moved before this change: its `bun-terminal-host.ts:510-511` reference was verified as `bun-terminal-host.ts:510-512` on the starting tree. After this change, the corresponding framed-paste and Enter writes are `bun-terminal-host.ts:519-522`.

The old distinctive sentence was checked across the module with `rg -n "TEXT FIRST, THEN THE SUBMIT|PASTE FIRST, THEN THE SUBMIT" runtime/adapters/claude-code/persistent`. The positive control found the replacement at `bun-terminal-host.ts:514`; there were no remaining old-phrase hits.
