## 2026-09-15 — open pull requests cannot claim the same migration ordinal

### What changed

The new check extracts only added top-level migration files (`scripts/ci/open-pr-migration-ordinal-check.ts:7-17`), fetches every open pull request and every changed-file page (`scripts/ci/open-pr-migration-ordinal-check.ts:40-53,88-104`), excludes the current pull request from comparison (`scripts/ci/open-pr-migration-ordinal-check.ts:25-29`), and reports every collision with the current number, other number, and ordinal (`scripts/ci/open-pr-migration-ordinal-check.ts:106-108`). A pull request without migrations has an empty ordinal set and therefore no collision (`scripts/ci/open-pr-migration-ordinal-check.ts:23-29`).

The workflow grants read-only pull-request access and runs the check on pull-request events (`.github/workflows/ci.yml:225-227,396-400`). The bare pull-request trigger covers opening and later updates (`.github/workflows/ci.yml:216-220`), so the check is maintained by Actions rather than relying on either colliding build lane to discover the other one.

An added ordinal greater than the base maximum plus one produces a warning (`scripts/ci/open-pr-migration-ordinal-check.ts:34-38,109-112`). Reading the base and GitHub API both fail closed when their answers are unavailable (`scripts/ci/open-pr-migration-ordinal-check.ts:47-49,55-67,81-91`).

### Decisions

The existing main-branch guard remains because it detects a different state: a checked-out migration conflicting with history (`scripts/ci/migration-ordinal-guard.sh:54-81`). The new API check owns the cross-pull-request state that git history cannot contain (`scripts/ci/open-pr-migration-ordinal-check.ts:88-108`). These are complementary checks, not selectable paths.

The outcome joins the workflow step exit vocabulary: collision exits 1, unavailable evidence exits 2, and success exits 0 (`scripts/ci/open-pr-migration-ordinal-check.ts:116-129`). Actions' default handling makes either nonzero outcome fail the layering job because the workflow step has no permissive override (`.github/workflows/ci.yml:396-400`). Gap detection is advisory because historical migration gaps are intentional (`migrations/runner.test.ts:158-165`).
