## 2026-09-16 — Keep the stored GitHub credential out of the build suite (#1058)

### Change and acceptance

The suite now uses plain `spawnCapture`, with an optional test injection seam,
instead of the publication runner (`open/wiring/project-build.ts:57-59,352`).
The host selects this runner on every suite invocation; it does not rely on the
suite cooperating or scrubbing its own environment. Publication still receives
`context.runHost` (`open/wiring/project-build.ts:316`).

Acceptance: a real suite child must observe none of the fields supplied by
`githubProcessEnv`, while a real local `git push` must retain the injected token.
The regression enumerates those fields from the actual helper, reads the suite
transcript, and observes the push environment through a pre-push hook
(`open/__tests__/project-build-wiring.test.ts:570-607`;
`github/credential.ts:122-132`). Existing receipt, timeout, transcript and parser
assertions were moved to the suite test seam without relaxing their expectations
(`open/__tests__/project-build-wiring.test.ts:104-115,422-565`). The end-to-end
fixture routes both runners through its command recorder
(`open/__tests__/project-build-e2e.test.ts:524`).

### Investigation and decisions

Verified the defect on the supplied local `origin/main` with
`git grep -n -E 'makeLazyCredentialedHostRunner|credentialEnv' origin/main -- trident/git-mode.ts open/composer.ts`.
The runner symbol is the positive control; it matches both definition and wiring.
The supplied base is `519a0f39`. The filed composer's line 2217 is now
`open/composer.ts:2238`; the filed `trident/git-mode.ts:1293-1294` is unchanged.
The suite call was `open/wiring/project-build.ts:348`, now line 352.
These are all filed citation corrections, enumerated by reading the full brief.

Enumerated direct `context.runHost(` calls in `open/wiring/project-build.ts`
with `rg -n`: the original lines 184, 198 and 348 were git preparation and the
suite shell. A broader `runHost\(|run_host\(` search across production TypeScript
in `trident/` also found non-git commands: tar
(`trident/production-host-effects.ts:290`), cleanup bash (:428), chmod
(`trident/review-run.ts:473`), and ps (`trident/run-evidence-probes.ts:208`).
These are examples from that search, not an exhaustive call-graph audit.

Chose a separate suite runner over a global executable-name allowlist: cleanup
also needs remote git verification (`trident/worktree-cleanup.sh:31-34`).
The existing plain mutation subprocess runner was inspected, and only its
limited no-injection property was used as precedent
(`trident/mutation-prover.ts:4019-4025`).

The existing outcome vocabulary remains `HostCommandResult` receipts and the
review suite assessment. Timeout and unavailable transcript omit the exit
receipt (`open/wiring/project-build.ts:355-359`); a missing receipt becomes
`unknown`, while a nonzero suite exit is classified by existing evidence rules
and defaults to a blocker (`trident/gates/review-suite.ts:41-50`). This change
introduces no new error, refusal or product decision.
