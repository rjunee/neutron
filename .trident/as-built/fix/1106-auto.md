## 2026-09-17 — distinguish REPL consumption at dispatch expiry

### What changed

The Claude acting turn now keeps the exact submitted dispatch line and classifies
the session transcript once when the dispatch deadline expires
(runtime/workers/claude-acting-turn.ts:98-112). A readable user record containing
that exact line is `consumed`; a readable transcript without it is
`not-consumed`; a failed transcript read is `unreadable`
(runtime/workers/claude-acting-turn.ts:43-60).

Those three observations produce distinct details while remaining in the
existing `unknown` outcome. The project runner already maps any acting-turn
uncertainty into `unknown` (runtime/workers/project-runners.ts:138-146), so no new
outcome value or unclassified default was introduced. The transcript read is
outside the polling work and occurs only in the dispatch-deadline branch
(runtime/workers/claude-acting-turn.ts:102-121), so transcript size does not
become a per-poll cost.

The logical-clock test supplies a matching transcript only at the deadline, a
readable non-matching transcript only at the deadline, and no readable transcript
for the third state (runtime/workers/claude-acting-turn.test.ts:332-347). It
asserts the three distinct details, the unchanged `unknown` kind, and the fixed
dispatch boundary (runtime/workers/claude-acting-turn.test.ts:361-375).

### Decisions

Only an exact user-message match counts as consumption. The classifier accepts
the two transcript content shapes already used in this tree: a string or a text
content block (runtime/workers/claude-acting-turn.ts:52-57). Malformed and
unrelated records do not assert consumption (runtime/workers/claude-acting-turn.ts:50-60).

The existing subagent metadata observation still takes precedence: once matching
metadata is seen, the acting turn continues waiting for its trailer rather than
reclassifying dispatch delivery (runtime/workers/claude-acting-turn.ts:110-120).

### Deliberate limits

This change does not infer worker completion from transcript consumption, replay
an uncertain dispatch, add a feature flag, or create a second dispatch path. It
does not change `SPEC.md`: the product decision and outcome vocabulary are
unchanged. It also does not read the transcript on every poll; the one-shot
boundary read is the timing-preserving constraint implemented here
(runtime/workers/claude-acting-turn.ts:111-112).
