## 2026-09-17 — unarmed reservation cleanup; #1122 remains open

### Scope and decision

This change does **not close #1122**. The cleanup primitive is implemented, but the claimed recovery of a pending, uncheckpointed same-run attempt is not delivered. Remove any PR closure keyword for #1122. This correction follows the task brief's explicit alternative to changing the existing terminal decision.

The normative comment at `trident/orchestrator.ts:2916-2917` says: “Resume only from the durable build evidence, never by replaying an uncheckpointed reservation.” The guard requires branch, checkpoint and checkpoint head (`trident/orchestrator.ts:2918-2924`). The existing acceptance control requires an uncheckpointed prior-gateway reservation to fail with zero launches (`trident/orchestrator.test.ts:474-492`). A settled driver unknown also becomes terminal, with the comment requiring “unknown must fail visibly, not park” (`trident/orchestrator.ts:2972-2982`). These are deliberate contracts, not permission to clear any pending result.

“A later attempt” can mean checkpoint-backed recovery of the same run, or a new-run retry. The spec explicitly says “A re-dispatch creates a NEW run row” (`docs/spec-items/a-retry-must-resume-from-the-checkpoint.md:10-11`). Preparation keys reservation storage by `encodeURIComponent(run.id)` (`open/wiring/project-build.ts:226`). Consequently the old reservation cannot obstruct the new run's directory. The filed stale-file problem is about the **same run**, and interpreting it as new-run retry would not establish a fix.

The prior-gateway session marker identifies a dead in-process promise (`trident/project-launcher.ts:63-70`), but is not sufficient authorization to replay work. The orchestrator first requires durable continuation, then claims recovery (`trident/orchestrator.ts:2914-2957`); the store atomically clears the old result and increments the recovery budget (`trident/store.ts:1548-1564`). That admitted path can reach preparation. A pending row instead returns before preparation (`trident/project-launcher.ts:116-123`). This review therefore preserves the terminal decision and withdraws the broader closure claim. Same-run recovery without a checkpoint requires an explicit superseding product decision.

### What is implemented

The helper selects recognized reservation files, preserves armed bytes and removes unarmed files (`runtime/workers/trailer-slot.ts:48-86`). Preparation calls it before constructing runners (`open/wiring/project-build.ts:226-238`). Its caller must first establish exclusive admission; reaching this helper does not itself establish that a pending run may restart (`runtime/workers/trailer-slot.ts:50-57`). Launcher compare-and-swap and terminal-row exclusion maintain admission independently of the dead process (`trident/project-launcher.ts:120-123`; `trident/store.ts:1050-1056`).

The four filename families were enumerated with `rg -n 'reserveTrailerSlot' runtime/workers`, which also found the helper definition as a positive control: Claude at `runtime/workers/claude-in-repl.ts:48`, Codex at `runtime/workers/codex-in-repl.ts:49`, Pi at `runtime/workers/pi-in-repl.ts:60`, and headless Codex at `runtime/workers/codex-headless.ts:137`.

No new outcome vocabulary is introduced. Worker uncertainty joins the existing `unknown` switch, which stops the driver (`trident/build-run.ts:364`). Cleanup failures throw during preparation (`open/wiring/project-build.ts:231-232`) and use the existing launcher `failed`/`inner-error` disposition (`trident/project-launcher.ts:170-172`).
