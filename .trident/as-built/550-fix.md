## Issue #550 — scope web foreground presence by project

### What changed

Web foreground records now include the project selected by the socket, and a lookup matches both owner and project (`gateway/push/web-presence.ts:149-180`). The app-ws control-frame path supplies the socket's existing project coordinate, using `null` for General (`gateway/http/app-ws-surface.ts:881-888`). The push wrapper supplies the durable message's required project coordinate to that lookup (`gateway/push/web-presence.ts:215-236`), and Open composes the owner-specific lookup once around the shared push sink (`open/composer.ts:2817-2824`).

The complete production and test call-site set was enumerated with `rg -n '\.foreground\(|\.isForeground\(|suppressPushWhileWebForeground\(' gateway open --glob '*.{ts,tsx}'`. The positive controls were the known production reporter at `gateway/http/app-ws-surface.ts:885` and production lookup at `open/composer.ts:2824`; every enumerated tracker call now supplies a project coordinate.

### Decisions

The tracker stores `project_id: string | null` beside each connection instead of changing the presence wire frame. The socket already owns its sanitized project for its lifetime (`gateway/http/app-ws-surface.ts:318-362`), and every push input already requires its destination project (`gateway/push/chat-message-push.ts:236-243`), so both comparison operands come from authoritative existing boundaries.

General remains an explicit `null` scope. A tab on General therefore matches only a General message, just as a named-project tab matches only that named project (`gateway/push/web-presence.ts:178`).

This adds no error, verdict, state, or refusal. It joins the existing Boolean presence vocabulary: an exact fresh match returns `true`, while the default after enumerating live entries is `false` (`gateway/push/web-presence.ts:173-180`). An exception also retains the established notify-safe `false` default (`gateway/push/web-presence.ts:219-230`). The invariant is maintained continuously by recording scope on every foreground refresh and by pruning expired claims on reads (`gateway/push/web-presence.ts:151-180`); expiry does not depend on a failed browser sending a final frame.
