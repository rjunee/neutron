## Issue 1153 — distinguish a missing suite command from an unreadable receipt

### What changed

- `trident/gates/review-suite.ts:41-43` keeps the existing deferred-subset success, then classifies `report === null` as terminal `unknown` with `No full-suite command is derivable from the test strategy`; a present report with no integer `hostExitCode` retains the unreadable-receipt diagnostic.
- `open/wiring/project-build.ts:461-467` establishes the two source facts: failure to derive a command returns `report: null`, while an executed command with timeout or unavailable log omits the exit code from a present report.
- `trident/gates/review-suite.test.ts:49-60` asserts both distinct diagnostics. `open/__tests__/project-build-e2e.test.ts:817-827` drives the no-marker strategy through the composed host, asserts a review-phase `unknown`, and proves no suite command ran.

### Decision

`report === null` remains terminal `unknown`. A `full-suite` scope has no host receipt, so treating it like the deferred-subset exception at `trident/gates/review-suite.ts:41` would grant success without the required suite evidence. This is a different outcome and message from a present-but-unreadable report at `trident/gates/review-suite.ts:43`.
