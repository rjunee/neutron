## Issue #1136 — isolate the project-build persistent REPL sink port

### What changed

The persistent-session test now asks the operating system for a free loopback
port through the existing `reserveFreePort` test helper and supplies that port to
the substrate (`open/__tests__/project-build-wiring.test.ts:18-19`,
`open/__tests__/project-build-wiring.test.ts:823-832`). It therefore no longer
uses the default hash of the state directory. That default is intentionally
stable and admits hash collisions (`runtime/adapters/claude-code/persistent/sink-coordinates.ts:169-180`),
while an explicit option wins at the shared resolution chokepoint
(`runtime/adapters/claude-code/persistent/sink-coordinates.ts:231-257`).

The helper binds loopback port zero, reads the kernel-assigned port, and closes
the reservation (`tests/support/test-isolation.ts:146-169`). The kernel allocator
maintains the per-run uniqueness invariant independently of the persistent REPL
or any already-running gateway. The documented bind-then-use race is accepted
only for unit tests (`tests/support/test-isolation.ts:150-155`); production keeps
its restart-stable derived coordinate.

This adds no error, verdict, state, or refusal, so there is no outcome vocabulary
to extend. No feature flag or alternate production path was added.

### Decisions

The change is scoped to the one test fixture because restart adoption is not the
property it exercises; its assertions cover warm reuse and the spawned tool
surface (`open/__tests__/project-build-wiring.test.ts:817-865`). Changing the
production sink to port zero would violate the explicit restart-stability guard,
which rejects zero (`runtime/adapters/claude-code/persistent/sink-coordinates.ts:248-266`).

The repository helper was reused after checking its stated property and limit:
it exists for callers that need a numeric port before their component binds, and
documents the resulting race (`tests/support/test-isolation.ts:150-155`).

No `SPEC.md` decision or spec item changed because this corrects test isolation,
not product behavior.
