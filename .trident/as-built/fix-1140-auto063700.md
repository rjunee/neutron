### What changed

`ciUnknownDetail` validates the completed worker trailer and appends “Review
worker reported APPROVE; host receipt not obtained.” only for a schema-valid
`APPROVE` claim (`trident/build-run.ts:194-204`). The post-worker CI unknown
exit now uses that detail (`trident/build-run.ts:559-562`). The output remains
the existing `unknown` outcome; this change does not write `inner_verdict`.

The focused fixture proves the exact deferred-CI detail for an APPROVE trailer
and proves that a `REQUEST_CHANGES` trailer retains the host detail unchanged
(`trident/build-run.test.ts:1263-1298`). The existing disposition vocabulary
classifies `APPROVE` as `approved` and every other verdict through the
no-review path (`trident/run-disposition.ts:191-198`); its focused test includes
the `REVIEW_NOT_RUN` built-but-never-reviewed case
(`trident/run-disposition.test.ts:54-58`).

### Decisions

I reused `validateTrailer` because it establishes the limited fact needed for
an owner-facing attribution: the worker supplied a well-formed verdict trailer
(`trident/gates/result-contract.ts:252-256`). It is not panel verification; the
post-worker CI receipt gate still precedes `reviewGate`
(`trident/build-run.ts:559-564`). No verdict vocabulary, state, refusal, or
feature flag was added.
