## Issue 1093 — injected logger failures are observable

### Built

Added `invokeInjectedLogger`, which preserves the caller outcome while routing synchronous throws and asynchronous rejections into the existing `fireAndForget` vocabulary: the process-owned structured logger and rejection counter (`logger/fire-and-forget.ts:140-155`). The registration service, persisted-definition loader, context source, dispatcher, bundled seeder, and bundled-enable sweep now use it (`reminders/ritual-registration.ts:425-426`, `reminders/ritual-registration.ts:1208-1209`, `reminders/context.ts:58-59`, `reminders/dispatcher.ts:339-340`, `reminders/bundled-rituals.ts:159-161`, `reminders/bundled-ritual-enable.ts:154-155`).

The callback contracts now return `unknown`, accurately admitting async callbacks while each wrapper exposes a synchronous `void` surface.

### Decisions

Logger failures join `fireAndForget` rather than creating a new outcome. Its default is non-fatal visibility: increment the process counter, emit a structured error through the system logger, and swallow the rejection so diagnostics cannot replace the recovery result (`logger/fire-and-forget.ts:119-136`). The shared helper owns continuous enforcement and does not depend on the failed callback.
