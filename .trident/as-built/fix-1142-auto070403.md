## Issue #1142 — retry a run on its own published PR

### What changed

Board dispatch now carries a published PR number only from the terminal run named by the card's exact `linked_run_id`, and only when the prior task text still matches (`trident/board-dispatch.ts:1311-1339`, `trident/board-dispatch.ts:1515-1518`). The run store persists that proof on the new retry row (`trident/store.ts:437-438`, `trident/store.ts:865-868`), and project composition supplies it to the build driver (`trident/project-build-host.ts:104-110`).

Fresh admission now distinguishes the measured PR by number, open state, and exact head: the proven prior PR may continue, while every different, closed, or moved PR retains the existing refusal (`trident/build-run.ts:239-252`). The focused tests prove both directions (`trident/build-run.test.ts:224-249`). Dispatch coverage proves the ownership number is persisted for the retry and withheld from a different-task control (`trident/board-dispatch.test.ts:1710-1732`, `trident/board-dispatch.test.ts:1990-2012`).

### Decisions

This uses reclaim semantics rather than `bound_pr`. `bound_pr` selects the retained review-only executor, while this retry remains a build that may plan, build, review, publish, and merge; the distinction is made at the dispatch write (`trident/board-dispatch.ts:1515-1520`). No feature switch or parallel path was added.

PR ownership is maintained by the board's durable exact run link, not inferred from the truncated slug. Dispatch trims the link and loads that exact row (`trident/board-dispatch.ts:1311-1339`), then requires matching task text before carrying its PR (`trident/board-dispatch.ts:1516-1518`). The mechanism reads persisted state after the prior run is terminal and does not depend on that failed run still operating.

The fresh-PR refusal remains in the existing `BuildRunOutcome` vocabulary as `blocked`; an unreadable host measurement remains the separate `unknown` outcome (`trident/build-run.ts:37-38`, `trident/build-run.ts:138-146`, `trident/build-run.ts:239-252`). Therefore a new unowned PR defaults to the same orchestrator-addressed refusal as before, while an inability to measure never becomes a negative ownership verdict.

The filed citation `trident/build-run.ts:247` was exact before the edit. The refusal condition now begins at `trident/build-run.ts:251` because the new input member and explicit ownership measurement added lines above it. No other filed line correction was needed.
