# IMPLEMENTATION_PLAN — a fix round must be able to check out its own branch

Governing doc: `.trident` plan "A fix round cannot check out its own branch — the previous round's worktree still holds it, so round 1 dies as CODEX_BUILD_BRANCH_UNBOUND". Evidence: runs c5c5fb4a (PR #359) and ad6ac515 (PR #366) both died at the bind step in `trident/codex-build.sh` because the previous round's preserved worktree still held the run branch; both were unblocked by hand with `git -C <worktree> checkout --detach`.

- [x] RECLAIM AT BIND (`trident/codex-build.sh` + `trident/codex-build.test.ts`): when `git switch <branch>` fails because another worktree holds the branch, identify the holder from `git worktree list --porcelain`, prove no live process is standing in it (/proc cwd scan on Linux; bounded lsof fallback; unverifiable → refuse, fail-closed), then `git -C <holder> checkout --detach` — files preserved, branch freed — and retry the bind. Refuse (exit 3, before any token is spent) when the holder is live or is the shared main checkout; `git worktree prune` when the holder's directory is gone. Never signal any process. Tests: stale holder → reclaimed and built; live holder → still refused; holder files intact after detach; pruned-dir holder → bound. (Rewrites the existing "an unbindable branch defers" test, which asserts the pre-fix behavior.)
- [ ] RELEASE AT ROUND END (`trident/codex-build.sh` exits, + test): after `emit_trailer` on BOTH terminal paths (`ok` and `failed`), detach this worktree from the run branch (`git checkout --detach`, same commit, files untouched) so a worktree preserved for post-mortem never holds the branch ref into the next round. Must run strictly AFTER `emit_trailer` measures `branch_name`/`head` (it reads `--abbrev-ref HEAD`, and a detached HEAD reports as no-branch). Test proves: after a successful wrapper run the worktree's `git rev-parse --abbrev-ref HEAD` is `HEAD`, its files are intact, `refs/heads/<branch>` still points at the built sha, and the trailer still names the branch and sha. Verify `worktree-cleanup.sh` interactions: a detached worktree is no longer enumerated as a branch holder, which is the intent — commits are protected by its origin-sha gate, not by the checkout.
- [ ] NEVER STRAND A GREEN PR (`trident/inner-workflow.mjs`, orchestrator terminal-cause path, + test): when a fix round's build defers with `CODEX_BUILD_BRANCH_UNBOUND` (wrapper exit 3) and the run already carries an open PR from a prior round, the run must terminate in a state whose cause names that PR as complete and awaiting merge — not `inner-error` with a cause that reads as a build failure. Test drives a fix round whose build wrapper exits 3 with the UNBOUND marker on a run holding a PR number, and asserts the terminal cause names the PR and does not present as a build failure; a round-0 UNBOUND (no PR yet) keeps the existing deferral behavior.

## Do not (copied verbatim from the card's plan doc)

_Source: `docs/plans/a-fix-round-cannot-check-out-its-own-branch-the-previous-rou-cr2c0b.md`. Do not paraphrase this section._

- Do not delete preserved worktrees to solve this — they hold the post-mortem evidence that made tonight's diagnosis possible. Detach, do not destroy.
- Do not force-checkout the branch out from under a live worktree of another run; that is how two rounds end up committing to one branch.
