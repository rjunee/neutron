# IMPLEMENTATION_PLAN — Pre-build latency: instrument brief→build durably, attribute it, then cut it

Regenerated 2026-08-18 against main (89de7523). Card: every trident round burns ~10–16 min between "brief written" and `codex-build.sh` starting; the prior measurement (`/tmp` `.part` mtime vs `.err` birth) is invalid (`.part` is rewritten on re-fire → the negative 85d94d94 sample), and the fourth Open sample (937 s) falsified the tight-cluster/determinism argument. Order is load-bearing: nothing may be cut (task 4) before it is attributed (task 3), and nothing can be attributed until the stamps exist (tasks 1–2). Surveyed: no stage instrumentation exists anywhere in the tree today (grep `stage_events|stage-stamp|prebuild` → docs only); latest migration is 0131.

- [x] 1. **Durable stage-event ledger + every deterministic (non-prompt) writer.** Migration `0132_code_trident_stage_events.sql`: append-only `code_trident_stage_events` (run_id, stage, at, meta; STRICT; runtime code only ever INSERTs, so a lane killed mid-round keeps every completed-stage stamp — falsification criterion 1). New always-exit-0 `trident/stage-stamp.sh` (checkpoint.sh's hardening: same-invocation `busy_timeout=5000`, sql_quote, ms-UTC stamp with the `%3N` BSD fallback; NEVER fails the command chain it rides in). Store: `recordStageEvent`/`stageEvents`. Orchestrator: best-effort `record_stage` seam stamping `launch-start` (meta `round=… ralph_round=…` — the re-fire discriminator), `fire-dispatched`, `fire-settled` inside `launch()`; wired to the store in `gateway/composition/build-core-modules.ts`. Wrapper: `codex-build.sh` stamps `wrapper-start` (top of execution, BEFORE the not-connected checks, so a refused lane still records) and `codex-exec-start` (immediately before `codex exec`), behind `NEUTRON_CODEX_BUILD_STAGE_SCRIPT` threaded `buildWorkflowArgs` → `inner-workflow.mjs` → the detached launch command's env block. This alone measures the whole brief→build window (`fire-dispatched` → `wrapper-start`) durably and splits host cost from inner cost.
- [x] 2. **Workflow-side stage stamps piggybacked on EXISTING agent turns** — adding an `agent()` step would add minutes of exactly the latency being measured, so zero new LLM turns is a hard rule. `plan-start`: a leading "FIRST run exactly this one Bash command, then proceed; never let it affect your work" instruction in `planFablePrompt`, and command 0 of `planProbePrompt` (`planNextPrompt` runs no commands by its own contract — leave it untouched). `build-agent-start`: an explicit stamp Bash call in `codexBuildPrompt` before chunk CALL 1, worded so the bridge never merges it into a chunk write, plus a leading stamp in the Claude-route forge contract. `wrapper-invoke`: folded into the detached launch command line itself (`bash <stage-stamp.sh> <db> <run> wrapper-invoke; rm -f …; nohup setsid …`) so it is deterministic given the bridge runs the line at all. All gated on `dbPath && runId`, exactly like `checkpointEnv`.
- [x] 3. **Attribution reader.** A deterministic per-fire stage-split report over the ledger: group a run's events into fire windows at each `launch-start`, compute the named segments (fire-dispatched→fire-settled, fire-settled→plan-start, plan-start→build-agent-start, build-agent-start→wrapper-invoke→wrapper-start, wrapper-start→codex-exec-start) with per-run durations and percentage split, aggregated per project; bun-runnable against the live DB; unit-tested over seeded fixtures including re-fire interleavings and missing stages (a best-effort stamp may be absent — report "unattributed", never invent). DONE when the dominant contributor can be named with a percentage from ≥5 instrumented runs per project and the earlier 605 s / 966 s figures are reproduced or explained (criteria 2–3). The report must print sample counts and refuse a conclusion under n=5 rather than extrapolate — the 5-run accumulation is operational, not buildable.
- [ ] 4. **The cut — design GATED on task 3's measured attribution; do not start until the dominant contributor is named with a percentage.** Candidates from the card, none yet justified: cache/skip re-planning on a fix round, shrink the brief, parallelise compose with worktree setup, start the wrapper before non-essential planning completes. DONE when mean brief→build drops on ≥5 fresh runs per project, before/after quoted from the task-1 ledger (criterion 4).

Guardrails (binding, from the card): do NOT optimise against brief size before it is measured; do NOT derive latency from `/tmp` `.part` mtimes ever again; do NOT add a lock/queue/concurrency cap for the retracted contention theory; do NOT re-investigate repo size, `infra_retries`, `DEFAULT_SETTLE_TIMEOUT_MS`, or `MAX_CONCURRENT_SUBAGENTS`. Instrumentation must never fail a build or a launch, and must add zero LLM turns.
