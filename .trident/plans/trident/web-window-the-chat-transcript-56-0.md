## Planning decisions (2026-08-31, verified against the tree — do not re-derive)

- **Window at the runtime seam, not inside assistant-ui.** `vm.messages` flows `MountedConversationImpl` → `ConversationRuntimeHost` → `useChatRuntime`/`useChatAdapter` (`landing/chat-react/useNeutronChat.ts:165-172`) → `ThreadPrimitive.Messages` mounts one bubble per adapter message. Slicing the array handed to `ConversationRuntimeHost` bounds the DOM of EVERY surface (active AND the up-to-8 hidden keep-alive surfaces) without touching the library or the keep-alive cache.
- **Anchor-by-id, not slice-by-count.** State per surface is `olderAnchorId: string | null` (`RenderMessage.id` is stable — `controller.ts:84-91`). `null` ⇒ pure trailing `slice(-N)`. After a "Load older" the start is PINNED by id, so live arrivals GROW the rendered list instead of shifting every index (assistant-ui renders messages keyed BY INDEX — `@assistant-ui/core` ThreadMessages.js — so a shifting front would re-point every mounted bubble and could hop in-progress per-bubble edit state). In trailing mode arrivals shift the window forward by design; the newest message is always mounted.
- **Identity-preserving short-circuit is load-bearing.** When `messages.length <= N` the windowed array must BE `hostVm.messages` (same reference). `useChatAdapter` memoizes on `vm.messages` identity (#354 notify-storm guard), and `__tests__/switch-render-cost.test.tsx` pins conversions=0 / exact per-switch surface renders on small transcripts. The short-circuit keeps every existing test's world bit-identical.
- **Reset on the DEACTIVATION edge** (`active` true→false), via a bail-out-safe updater (`setOlderAnchorId(prev => prev === null ? prev : null)`), so a surface the user extended shrinks back to trailing N while hidden, switch-INTO does zero extra work, and no render is scheduled when already trailing (protects switch-render-cost's exact render-identity assertions). Shrink happens through a normal React state update → adapter → runtime notify (never an in-place array mutation), which is the supported path; the new test asserts the ChatErrorBoundary does not fire on it.
- **Scroll preservation on load-older** exactly as the card prescribes: capture viewport `scrollHeight`/`scrollTop` at click; restore `scrollTop += ΔscrollHeight` in a `useLayoutEffect` keyed on the RUNTIME's rendered message count (`useAuiState((s) => s.thread.messages.length)`) — the extension lands one commit AFTER the click (adapter is applied in `useExternalStoreRuntime`'s effect), so a parent-keyed effect would run too early. Pre-paint restore = no flash; `isAtBottom` is false at the top so `useThreadViewportAutoScroll` does not fight it.
- **Verified absent, state in PR instead of building:** no deep-link/scroll-to-message path and no in-page transcript search exist in `landing/chat-react/` (grep: `scrollIntoView|getElementById|location.hash` → only ActivityInspectorPanel's own panel + main.tsx root; no search UI). Day dividers (`metaCtx`) are computed over the FULL list; the window top may open mid-day — cosmetic, accepted.
- **Deliberately omitted:** IntersectionObserver auto-extend (card allows omission; the explicit control is the requirement and carries less scroll-anchor risk); any virtualization library; reachability-inventory entry (its harness has no long-transcript fixture — the new component test clicks the real button in the real mounted ChatApp).
