# IMPLEMENTATION_PLAN — Deterministic brief composition: the launcher's disk copy is the single authority

Regenerated 2026-08-16 against main (4eb3adc). Card: eliminate CODEX_BUILD_BRIEF_ARGS_CORRUPT dispatch refusals. Root cause (verified in code): the reflection/task segments are composed once by the launcher (`trident/inner-loop.ts` → `buildReflectionGuidance` + `writeBriefParts`, receipts on disk) and then travel A SECOND TIME as free text through the fire-launcher bridge model inside the workflow args JSON (`buildFireWorkflowPrompt` embeds `argsJson`; the model retypes it). `codexBriefByPath` (inner-workflow.mjs ~1429) measures the ARGS copies against the launcher's receipts and THROWS `CODEX_BUILD_BRIEF_ARGS_CORRUPT` on any divergence — so a bridge that mangles one em dash/ellipsis in a 4 KB capped block kills the dispatch, even though the authoritative bytes are already sitting on disk where the wrapper assembles from. Additionally the whole-file receipt `NEUTRON_CODEX_BUILD_BRIEF_INTEGRITY` is computed from the args text, so merely deleting the throw would move the same refusal into the wrapper (`CODEX_BUILD_BRIEF_CORRUPT`). The fix: the disk manifest becomes the single authority for the brief's middle; args are demoted to advisory; the wrapper verifies PER-PART receipts (the only decomposition that works — FNV-1a over a concatenation cannot be derived from standalone segment hashes, and inner-workflow.mjs has no fs, so it can never measure the disk copies itself).
