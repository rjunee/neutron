# IMPLEMENTATION_PLAN — A finished build must not be thrown away when the push credential blinks (publish is retryable, not a rebuild)

Regenerated 2026-08-16 against main (4eb3adc). Card: `a-finished-build-must-not-be-thrown-away-when-the-push-crede-rbbjj2`. Measured incident: runs `9bb31a2e`/`9e0f1a8b` reached `forge-done`, then died at the push rung with `fatal: could not read Username for 'https://github.com'` — an intermittent credential absence (same publisher pushed fine at 08:38/08:42/08:49, failed at 09:04/09:10). Today `applyResult`'s `publish_requested` catch (orchestrator.ts ~1557) routes EVERY publish failure to `failedRun(...)` — terminal — and a re-dispatch creates a fresh row with NULL checkpoints, so a finished, reviewed commit is rebuilt from scratch. The work survives on `refs/heads/<branch>` in `run.repo_path` (verified: `trident/work-board-row-state-a-card-must-no` @ a96eb95, unpushed); `publishBuiltCommit` needs only that ref plus its own throwaway rebase worktree, so a later re-publish needs NO build worktree and NO Forge.

This is the #259 fix the card credits; the credential/rejection words ARE in the stored reason today — what is missing is a deterministic reading of them.

A re-publish attempt re-enters this same path; its idempotence over an already-rebased branch is existing behaviour to lean on, not to rebuild.
