Design decisions locked by this regeneration (the executor does not re-litigate):
- CLAIM RELEASE IS BY LIVENESS QUERY, never an explicit clear. The overlap check reads only non-terminal `code_trident_runs` rows (`phase NOT IN ('done','failed','stopped')`), so a run going terminal — by harvest, cancel, crash-reap, anything — releases its claim by definition. No release write exists to be missed, which is what makes "a stuck claim must not wedge the queue forever" structurally true.
- A HELD DISPATCH LEAVES ZERO `code_trident_runs` STATE (preserving the chokepoint's existing invariant); the only durable state is a row in the new `code_trident_dispatch_holds` table, upserted keyed on `(project_slug, board_item_id)`.
- THE QUEUE DRAINS ON THE TERMINAL OBSERVER: the sweep is composed as a trident terminal observer AFTER `buildBoardReconcileObserver` (so a blocker card's `status='done'` is already written when held cards re-evaluate). Re-dispatch goes back through `dispatchBoardBoundBuild` itself, so every gate re-runs and a still-held card just refreshes its hold row.
- PATH DERIVATION SOURCE (what is actually available, stated per the card): the card's plan doc when `design_doc_ref` is a `neutron-docs:` ref (resolvable at `<owner_home>/Projects/<project_slug>/docs/<path>` — the dispatch already holds the owner home as `deps.repo_path`), plus the task text always. Pure token extraction, no fs existence check — a path the build will CREATE still collides. Empty derived set → `claimed_paths = []`, dispatch proceeds (cannot hold on unknown).
- BLOCKER SEMANTICS: unmet = the blocker card exists with `status != 'done'`. A blocker id that resolves to NO card is treated as cleared (the removal chokepoint hard-deletes cards; waiting forever on a ghost would wedge the queue — judgment call, documented in code). A `failed` blocker keeps the hold and the message says the blocker FAILED, so the owner knows auto-release waits on its retry.
- OVERLAP SCOPE: same `repo_path` only — different projects build in different workspaces and cannot collide on files.
