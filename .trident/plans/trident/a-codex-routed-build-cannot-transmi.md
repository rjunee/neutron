# IMPLEMENTATION_PLAN — a codex-routed build cannot transmit a mutation nomination, so the merge gate refuses its PRs

Card: `mutationClaim` is structurally unreachable on the codex build route — the schema field is filled by the codex BRIDGE, which never sees the build's reasoning; the wrapper trailer is six lines of repository facts with no nomination line; `forgeBuildContract`/`codexBuildPrompt` never ask for one — so every codex-routed APPROVE reaches the post-APPROVE mutation gate with `claim: null` and is refused ("mutation proof required but the build nominated no mutation to run"). Fix: give the nomination a channel from the process that did the work to the value the gate reads; keep it untrusted; keep absence meaning null.

Resume state (branch `trident/a-codex-routed-build-cannot-transmi`): ONE squashed commit past its base plus THIS round's fix commit. Do NOT cite commit shas here — the branch is replayed onto a moving base every round and any sha written down is stale by the time it is read; `git log --oneline main..HEAD` is the only honest answer. Keep committing on this branch. A worktree WITHOUT its own `node_modules` fails trident/orchestrator.test.ts en masse with "table code_trident_runs has no column named claimed_paths" (workspace imports resolving into another checkout); `bun install --frozen-lockfile` in the worktree fixes it — environment artifact, not a regression. The ROOT `IMPLEMENTATION_PLAN.md` must be persisted with THIS body; mirror it to `.trident/plans/trident/a-codex-routed-build-cannot-transmi.md`.

## DESIGN DECISION (locked in the committed card plan — do not re-litigate) — Option A, refined: the nomination is a COMMITTED artifact, read back out of git at the gate call site

The build writes `.trident/mutation-claims/<branch>.json` — PER-BRANCH, mirroring `.trident/plans/<branch>.md` — and COMMITS it with its work; the orchestrator falls back to `readCommittedMutationClaim(opts.run_host, run.repo_path, { expected_head, branch, base_branch })` ONLY when `result.mutation_claim` is null. Committed-and-read-from-git rather than a loose worktree file or Option B's seventh trailer line because: (1) in pr mode the workflow process ENDS at every publish handoff and re-enters with `mutationClaim = null` — the schema field only survives to the gate in local mode, so ANY in-process carry dies at that boundary; a committed blob is the one channel that already crosses it (prior art: `.trident/plans/`, `.trident/as-built/`; not gitignored). (2) The build worktree belongs to a dead process at harvest time; the reviewed OID is durable and binds the nomination to the very commit the gate pins — tip movement already collapses into the gate's existing expected-vs-pinned refusal. (3) No wrapper change, no bridge change; the trailer stays wrapper-measured facts, which a model claim is not. Untrust preserved: the artifact is branch-controlled input, shape-decoded by the SAME `parseMutationClaim` the agent route uses, then validated and actually RUN by the unchanged gate; every absence/failure decodes to null (today's refusal); a schema-supplied claim always wins and the reader is not even invoked then (`??` short-circuit). `trident/mutation-prover.ts` is never modified (PR #490 owns it) — only its existing exports are imported.
